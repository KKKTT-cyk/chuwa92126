# Java Exception, Enum, and Collection Homework

## 1. Why must a checked exception be caught or declared while an unchecked exception does not require either?

Answer:

A checked exception must be caught or declared because the Java compiler checks it at compile time and requires the programmer to handle it.

An unchecked exception is a RuntimeException, so the compiler does not require it to be caught or declared.
---

## 2. Why must a catch block for a subclass come before a catch block for its superclass?

Answer:

A catch block for a subclass must come before a catch block for its superclass because the superclass catch can also catch subclass exceptions.

If the superclass catch comes first, the subclass catch becomes unreachable and causes a compile-time error.
---

## 3. What happens to an AutoCloseable resource when an exception occurs inside a try-with-resources block?

Answer:
When an exception occurs inside a try-with-resources block, the AutoCloseable resource is automatically closed.

Java calls the resource's close() method, so the programmer does not need to close it manually in a finally block.
---

## 4. How do throw and throws differ in where they are used and what they do?

Answer:
throw is used inside a method body to actually throw an exception.

throws is used in a method signature to declare that the method may throw one or more exceptions.
---

## 5. Why can returning a value from a finally block hide an exception?

Answer:
If a finally block returns a value, that return can replace what happened before it.

So even if an exception was thrown in the try block, the method may return the value from finally instead, which hides the exception.
---

## 6. How can an enum use a field and a method to store and return a value?

Answer:
An enum can have a field to store a value for each enum constant, and a method can return that stored value.

For example, SPRING(1) can store 1 in a field, and getValue() can return it.
---

## 7. When would you choose an ArrayList instead of a LinkedList?

Answer:

I would choose an ArrayList when I need fast access by index and do not need to frequently insert or remove elements in the middle.

ArrayList is usually better for reading elements, while LinkedList is more useful for frequent insertions and removals.
---

## 8. How do HashSet and LinkedHashSet differ when you iterate over their elements?

Answer:
HashSet does not guarantee the order of elements when you iterate over it.

LinkedHashSet keeps the insertion order, so elements are usually returned in the same order they were added.
---

## 9. How do HashMap and TreeMap differ in the order of their keys?

Answer:
HashMap does not guarantee any specific order for its keys.

TreeMap keeps its keys sorted, usually in their natural order.
---

## 10. Why is an Iterator useful when removing elements from a collection during iteration?

Answer:
An Iterator is useful because it allows elements to be removed safely while iterating through a collection.

Using Iterator.remove() avoids problems such as ConcurrentModificationException that can happen when removing elements directly from the collection during iteration.
