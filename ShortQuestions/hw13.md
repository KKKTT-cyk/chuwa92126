# Homework 13 - Java Advanced Syntax II

## 1. Dynamic Proxy

`Proxy.newProxyInstance()` creates an instance of a runtime-generated proxy class (the class may be reused). The class extends Proxy and implements the supplied interfaces.

For intercepted calls, `InvocationHandler.invoke()` receives the proxy object, a Method describing the call, and an Object array of arguments (possibly null for no arguments). The handler can add logic and delegate to a real object. Calls to equals, hashCode, and toString also reach the handler.

JDK dynamic proxies implement interfaces rather than subclassing the target class. The generated class already extends Proxy, and Java does not support multiple class inheritance. Other proxy mechanisms can use subclasses.

When delegating through reflection, unwrap InvocationTargetException so the caller receives the target's original failure:

```java
try {
    return method.invoke(target, args);
} catch (InvocationTargetException e) {
    throw e.getCause();
}
```

Otherwise, the reflection wrapper can become an UndeclaredThrowableException. Even after unwrapping, a checked exception not declared by the interface method can still be wrapped that way.

## 2. Class Loading

1. **Loading:** find the class bytes and create its runtime Class representation.
2. **Linking:** verify the bytecode, prepare static storage with default values, and resolve symbolic references. Resolution can happen lazily.
3. **Initialization:** execute static field initializers and static blocks in their declared order.

Initialization happens before active use: creating an instance, calling a declared static method, or reading/writing a declared static field that is not a compile-time constant. It also happens for the startup class, reflective operations that require initialization (such as Class.forName with initialization enabled), and certain method-handle invocations. Superclasses initialize first; superinterfaces that declare default methods are also initialized when required during class initialization.

A class literal, creating an array of that class, or reading a compile-time constant does not initialize the class. Reading an inherited static field initializes its declaring class, not necessarily the subclass used to name it.

The three built-in loaders are:

- **Bootstrap:** loads core runtime classes; it has no parent.
- **Platform:** loads additional Java platform classes; its parent is bootstrap.
- **Application/System:** normally loads application classes and dependencies; its parent is platform.

In the usual parent-first model, a loader checks whether the class is already loaded, then asks its parent before trying its own lookup. This helps share core class definitions and prevents application classes from replacing them. Custom loaders can use other delegation rules.

## 3. Java Serialization

- `serialVersionUID` identifies the serialized version of a class. A mismatch between the stream and the local class normally causes InvalidClassException. Declare it explicitly to avoid accidental changes to the computed value; matching values alone do not guarantee every class change is compatible.
- `transient` excludes an instance field from default serialization. It normally has its default value after deserialization unless custom code restores it. It is not encryption, and custom serialization can still write that data.
- `readResolve()` can replace a deserialized object with another object, such as an existing singleton instance.

Untrusted serialized data can trigger dangerous deserialization callbacks and gadget chains, or exhaust memory and CPU with large object graphs. Avoid native Java deserialization for untrusted input. If it is required, use restrictive ObjectInputFilter rules, size/depth limits, and validation; filters do not make arbitrary input automatically safe.

## 4. Expression Tree

The implementation is in `org.tiff.homework13.question4` and uses Java 21 pattern switches and record patterns. There is no default branch, so each switch covers every permitted Expr type.

`eval()` evaluates recursively and reports unknown variables. `show()` formats each expression. `simplify()` simplifies children first, then follows the listed rule order, including constant folding before zero/one rules.

```java
Expr expr = new Add(new Num(0),
        new Mul(new Num(1), new Neg(new Neg(new Var("x")))));

Exprs.show(expr);                    // (0 + (1 * --x))
Exprs.eval(expr, Map.of("x", 5.0)); // 5.0
Exprs.show(Exprs.simplify(expr));     // x
```
