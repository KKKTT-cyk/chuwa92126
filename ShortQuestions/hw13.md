1. Explain the difference between a static nested class and an inner (non-static) class. Describe the hidden reference an inner class holds, how it can cause a memory leak, and why a static nested class is usually preferred.

Static nested class does not need an instance of the outer class, while non-static inner class does.
Inner class holds a hidden reference to its outer object. If the inner object lives for a long time, it may prevent the outer object from being garbage collected, which might cause memory leak. Static nested class avoids this unnecessary reference, uses less memory, and is easier to create and test.


2. Explain type erasure: what the compiler does with `List<String>`, why `new T()`, `new T[10]` and `obj instanceof List<String>` are not allowed, and what a bridge method is and why the compiler generates it.

Type erasure is the compiler removes generic type information after checking types. For example, `List<String>` becomes a raw List at runtime, and the compiler inserts casts when needed.
- `new T()` is not allowed because the actual type of T is unknown at runtime.
- `new T[10]` is not allowed because arrays need to know element type at runtime.
- `obj instanceof List<String>` is not allowed because the generic type argument is erased.
Bridge method is a synthetic method generated by compiler to preserve method overriding after type erasure.


3. State the PECS rule. For `List<? extends Number>` and `List<? super Integer>`, say which operations (reading, adding) are allowed on each one and why, and explain why generics are invariant while arrays are covariant.

PECS: Producer Extends, Consumer Super
`List<? extends Number>` allows reading values as Number but cannot add values except null because the exact subtype is unknown.
`List<? super Integer>` allows adding Integer values, and values can only be read as Object because the exact supertype is unknown.

Generics are invariant, so `List<Integer>` is not a subtype of `List<Number>`. This prevents type errors at compile time. Arrays are covariant so `Integer[]` can be assigned to `Number[]`.


4. Describe the three retention policies (`SOURCE`, `CLASS`, `RUNTIME`) and what `@Target`, `@Inherited` and `@Repeatable` do. Which retention policy must an annotation have to be read through reflection at runtime?

- SOURCE discarded during compilation.
- CLASS stored in the class file but is not available through runtime reflection.
- RUNTIME is available through reflection at runtime.
- `@Target` specifies where an annotation can be used
- `@Inherited` allows subclasses to inherit class-level annotations
- `@Repeatable` allows the same annotation to be used multiple times

We must use RUNTIME retention to be read through reflection at runtime.


5. List the ways to obtain a `Class` object. Explain what `setAccessible(true)` does and how the module system limits it, and why a method invoked with `Method.invoke` wraps an exception thrown by the target in `InvocationTargetException`.
   
1. Class<?> c1 = Person.class; 
2. Class<?> c2 = Class.forName("Person")
3. Class<?> c3 = new Person().getClass()

`setAccessible(true)` allows reflection to bypass normal access checks, such as accessing private fields. Java module system may block access to packages that are not opened. `Method.invoke()` wraps exceptions thrown by the target method in an `InvocationTargetException` and helps distinguish exceptions from the target method from reflection-related errors. The original exception can be retrieved using `getCause()`.
