### Question 1.

A static nested class does not require an instance of the enclosing class, whereas a non-static inner class does. An inner class can hold a hidden reference to its enclosing object, commonly called `this$0`, allowing it to access outer instance members. If the inner object lives longer than the outer object's intended lifetime, it can prevent the outer object from being garbage collected and cause memory retention.

Static nested classes avoid this implicit reference to the outer instance, are easier to instantiate and test, and are gnerally preferred unless access to the enclosing instance is required. Modern java compilers can omit the hidden reference when it is unused.

### Question 2.

Java implements generics through type erasure. The compiler checks generic types, replaces type parameters with their bounds or `Object`, and inserts necessory casts. For example, `List<String>` becomes a raw `List` in the operational bytecode, although generic declaration metadata may remain. Because the concerete type parameter is unavailable at runtime, Java disallows `new T()`, `new T[10]`, and `instanceof List<String>`.

A bridge method is a synthetic method generated by the compiler to preserve polymorphism when type erasure changes methods signatures. It delegates to the actual overriding method.

### Question 3.

PECS stands for Producer Extends, Consumer Super. When a collection produces values we read, we use `? extends T`. For example, `List<? extends Number>` allows reading elements as `Number`, but not adding non-null elements because the exact subtype is unknown. When a collection consumes values we write, we use `? super T`. For example, `List<? super Integer>` allows adding Integer values, but reading only guarantees `Object`. Java generics are invariant to prevent type-unsafe writes at compile time, while arrays are covariant and enforce element compatibility through runtime checks, potentially throwing `ArrayStoreException`.

### Question 4.

Java has three annotation retention policies: SOURCE, CLASS, and RUNTIME. SOURCE annotations are discarded during compilation. CLASS annotations are stored in bytecode but are not accessible through standard runtime reflection, and CLASS is the default. RUNTIME annotations are retained and can be inspected through reflection. `@Target` controls where and annotation may be applied, `@Inherited` allows class-level annotations to be inherited by subclasses, and `@Repeatable` permits multiple occurrences of the same annotation using a container annotation. To read an annotation through reflection at runtime, it must have RUNTIME retention.

### Question 5.

Reflection allows Java to inspect classes and invoke methods or access fields dynamically at runtime. We can obtain a `Class` object using `MyClass.class`, `obj.getClass()`, or `Class.forName()`.
Callling `setAccessible(true)` requests suppression of Java language access checks so private members can be accessed reflectively, but the Java module system restricts deep reflection into packages that are not opened to the caller.
When `Method.invoke()` invokes a method that throws an exception, it wraps the original exception in `InvocationTargetException`, and we use `getCause()` to retrieve the actual exception.
