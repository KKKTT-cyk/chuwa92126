1.A cross-cutting concern is behavior used across many parts of an application, such as logging, security, or transaction management. In OrderService, logging code mixed into the order methods is tangling. Repeating the same logging code across multiple methods is scattering.
2.Aspect: A module that groups a cross-cutting concern, such as logging.  
Join point: A point during program execution where advice could run.  
Pointcut: A rule that selects join points.  
Advice: The code that runs at selected join points.  
Target: The original object whose method is advised.  
Proxy: The object Spring creates to intercept calls and apply advice.  
In Spring AOP, a join point is always a method execution.
3.Advice	When it runs	Can change return value or stop the target?
@Before	Before the method	Cannot change the value; can stop it by throwing
@AfterReturning	After normal return	No
@AfterThrowing	After an exception	No
@After	After return or exception	No
@Around	Before and after the method	Yes; it can change the value or skip proceed()
4.Not calling proceed() — the target method never runs.  
Calling proceed() twice — the target method runs twice.  
Not returning proceed()’s result — the caller may receive the wrong value, often null.
5.execution(* com.example.orders.service.*.*(..)) — all methods in classes directly inside service.
execution(* com.example.orders..*.*(..)) — all methods in orders and its subpackages.
execution(* *(Long, ..)) — methods whose first parameter is Long.
@annotation(com.example.orders.aop.LogExecutionTime) — methods annotated with @LogExecutionTime.
6.Spring wraps the target bean in a proxy that intercepts method calls and runs advice. The proxy is created after bean initialization, during the bean post-processing stage. Check with AopUtils.isAopProxy(bean).
7.A call from one method to another in the same class uses this, so it bypasses the Spring proxy. Fix it by calling the method through another Spring bean or by moving it to a separate bean.
8.By default, Spring rolls back for unchecked exceptions (RuntimeException) and Error, but not checked exceptions. A transaction may not roll back if the exception is checked, caught and not rethrown, or the call bypasses the proxy.
9.With @Order(1) on SecurityAspect and @Order(2) on TimingAspect, security runs first on entry and last on exit; timing runs inside it. Spring AOP uses runtime proxies and supports method-execution join points. AspectJ weaves code at compile time or load time and supports more join points, such as method calls and field access.
