### Question 1.

APF classifies API requests into priority levels with separate concurrency shares. It also queues requests fairly within each level. A noisy controller mostly fills its own queues and can receive `429 Too Many Requests`, while critical traffic such as node heartbeats still has capacity to run.

### Question 2.

Mutating admission can change an object, for example by injecting a sidecar. Validating admission checks the final object and allows or rejrects it. External webhooks add latency and an availability dependency. If the call fails, `Fail` blocks matching requests and `Ignore` lets them continue without that webhook.

### Question 3.

An informer uses list and watch to maintain a local cache. Event handlers enqueue object keys, and the work queue deduplicates pending work and supports retries with backoff. Workers reconcile each key by comparing desired state with observed state and making the API calls needed to close the gap.

### Question 4.

A level-triggered controller reads the current desired and observed state every time, so it can recover without replaying every event. Idempotency makes retries safe. A watch can resume or relist to repair the cache, a resync can revisit cached objects, and expectations or conflict retries help handle stale reads.

### Question 5.

A CRD adds a new type to the Kubernetes API. An operator watches instances of that type and implements their lifecycle. For example, a `Database Cluster` resource declares the desired cluster, and the Operator provisions it, manages upgrades and backups, and reports status.

### Question 6.

Requests are what the scheduler uses to place Pods. Limits constrain runtime usage. Capacity is what the node has, and allocatable is what Pods can use after reservations. QoS helps predict eviction under memory pressure. The kubelet looks at whether usage exceeds requests, then Pod priority and usage relative to requests.

### Question 7.

The scheduler filters out nodes that fail hard constraints, scores the feasible nodes, and selects the highest-ranked candidate. It accounts for the placement before binding so the next scheduling decision sees it. Binding records the assignment in the API server, and the kubelet starts the Pod.

### Question 8.

Node affinity places Pods based on node labels. Pod affinity and anti-affinity place them relative to other Pods. Taints repel Pods and tolerations allow them onto tainted nodes. Preemption can remove lower-priority Pods when doing so makes a node feasible for a higher-priority Pod.

### Question 9.

The kubelet coordinates Pod startup on the assigned node. It calls the container runtime through CRI to create the sandbox and manage images and containers. The runtime typically calls CNI plugins to configure the Pod's shared network namespace and IP connectivity.

### Question 10.

A Service gives clients a stable name, and EndpointSlices describe the changing set of backends. For a regular ClusterIP Service, CoreDNS returns the virtual IP and kube-proxy programs the data plane to route connections to eligible endpoints. For a headless Service, DNS returns backend IPs directly, so the client connects to a backend itself.
