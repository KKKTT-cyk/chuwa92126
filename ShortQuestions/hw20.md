APF (API Priority and Fairness) classifies API requests into priority levels and flows, then limits concurrency and queues requests fairly. A noisy controller can be throttled or queued so it does not consume all API server capacity needed by critical traffic. Kubernetes
Mutating admission changes an incoming object; validating admission accepts or rejects it. External webhooks add latency and can block API requests if they are slow or unavailable; fail-open settings can instead let requests through without the webhook’s check. Kubernetes
Informers list and watch objects, keeping a local cache and notifying handlers. Handlers enqueue object keys; workers read the cache and run reconciliation to make actual state match desired state.
Reconciliation should be level-triggered and idempotent so duplicate events and retries are safe. Controllers recover from missed events by relisting or resuming watches; if a cache is stale or a watch expires, they refresh state and reconcile again.
A CRD defines a new Kubernetes API type. An Operator combines custom resources with a controller that automates application-specific operations. Kubernetes
Requests describe resources a Pod needs for scheduling; limits cap resource use. Capacity is a node’s total resource amount; allocatable is what Kubernetes makes available to Pods. Under node pressure, eviction considers priority and resource use relative to requests; QoS is a useful indicator of likely eviction order. Kubernetes
The scheduler filters out infeasible nodes, scores the remaining nodes, reserves the selected node for the scheduling cycle, then binds the Pod to it. Kubernetes
Node affinity selects nodes by their labels; Pod affinity/anti-affinity places Pods based on other Pods’ labels. Taints/tolerations repel Pods unless they tolerate a node’s taint. Priority preemption may evict lower-priority Pods to make room for a higher-priority Pod. Kubernetes
The kubelet manages Pod startup on a node. It uses CRI to ask the container runtime to create the Pod sandbox and containers; the runtime invokes configured CNI plugins to configure Pod networking. Kubernetes
A Service provides a stable virtual address; its EndpointSlices list backend Pod addresses. kube-proxy programs node-level forwarding to those endpoints, while CoreDNS resolves Service names. A headless Service has no ClusterIP; DNS returns endpoint Pod addresses directly.
