### Question 1.

An imperative command tells Kubernetes what to do once. A declarative object records what should stay true. `spec` holds the desired state, and `status` reports observed state. Kubernetes controllers use events to trigger a fresh comparison. A later reconciliation can recover from a lost event, a restarted controller can rebuild its view from current state, and a duplicate event causes no extra action once the state matches.

### Question 2.

Kubernetes components coordinate through API objects. This gives them loose coupling, centralized policy, a common source of state, and a way to add controllers. The tradeoff is shared dependency on the API server and etcd. When two version-checked updates race, the first committed write wins. the other gets `409 Conflict`, rereads, and retries if needed. A watch with expired history gets `410 Gone` and recovers by listing again.

### Question 3.

A Pod is the smallest schedulable unit that runs the contrainers. A RepicaSet keeps the requested number of Pods present. A Deployment manages ReplicaSets to roll out or roll back application versions. A Service gives clients a stable address while Pods are replaced.

### Question 4.

The control plane manages cluster state, scheduling, and reconciliation. The data plane runs contrainer and forwards traffic. During a control-plane phase, exsting workload on healthy nodes generally continue servcing, while scheduling, rollouts, scaling, and cluster-level repair stall.

### Question 5.

Authentication identifies the caller. Autorization checks whether that caller can perform the requested action. Admission can modify or reject the proposed object before persistence. The API server validates and stores accepted objects, and controllers act on them asynchronously.

### Question 6.

`resourceVersion` supports optimistic concurrency and watch resumption. For a conditional update, the API server compares the submitted version with the stored version and returns `409 Conflict` if the submitted version is stale.

### Question 7.

List gives the client a starting snapshot and its `resourceVersion`. Watch streams changes after that version so the client can maintain a local cache. This saves bandwidth and processing by sending changes as they happen. If the watch history expires, the client lists again and starts from the new version.
