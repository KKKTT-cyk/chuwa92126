Imperative vs. declarative: An imperative command says what action to take now: “start three checkout copies.” A declarative object says what should be true: “there should be three checkout copies.” Its spec records the desired state; its status reports the observed state. Kubernetes controllers are level-triggered: they repeatedly compare current state with desired state and reconcile any difference. If an event is lost, a level-triggered controller can still detect the mismatch; if it restarts, it can reread state; if an event arrives twice, reconciliation remains safe because it works toward the same target. An edge-triggered controller relies on each event being handled exactly once, so it can miss work after a lost event or restart, or repeat work after a duplicate.
2. Why components use the API server: Components read and write shared API objects instead of calling one another directly. This gives them a shared source of truth, loose coupling, centralized access control and auditing, and a standard way to watch changes. The cost is extra API-server traffic and dependence on it for coordination. resourceVersion lets the API server detect stale updates: if two controllers read the same version, the first valid update succeeds; the other gets a conflict, rereads the object, reapplies its change, and retries. This optimistic concurrency avoids locks because the API server serializes writes and rejects stale ones. If a watch’s requested revision has been compacted, the client must list the current state and restart its watch from the returned revision. Kubernetes
3. Pods, ReplicaSets, Deployments, Services: A Pod runs one or more containers. A ReplicaSet maintains the requested number of matching Pods. A Deployment manages ReplicaSets and provides controlled rollouts and rollbacks. A Service gives a stable network address and routes traffic to matching Pods. Together, they run the application, replace failed Pods, and expose the healthy replicas to clients. Kubernetes
4. Control plane vs. data plane: The control plane stores and reconciles desired cluster state, schedules Pods, and manages cluster objects. The data plane consists of the nodes and networking that run workloads and carry their traffic. If the control plane is temporarily unavailable, existing workloads and Services generally continue running, but new scheduling and repairs or configuration changes that need the control plane may pause. Kubernetes
5. Creating an object: A client sends a request to the API server. The server authenticates the caller (who are you?), authorizes the requested action (may you do it?), applies admission controls (should this object be changed or rejected by policy?), validates and stores the object, then returns a response. Kubernetes
6. resourceVersion: This is an opaque version marker assigned by Kubernetes. Clients use it to detect changes and coordinate updates. Submitting an update based on an outdated version causes a conflict instead of silently overwriting another client’s newer change. Kubernetes
7. List and Watch: A client first lists objects to get a snapshot and its resourceVersion, then watches from that revision to receive subsequent changes. This avoids repeatedly fetching the full collection. If the watch history has been compacted, the client relists and starts a new watch. Kubernetes
