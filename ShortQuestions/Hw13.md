## 1. Explain how java.lang.reflect.Proxy works: what Proxy.newProxyInstance generates at runtime,what an InvocationHandler receives on every call, why only interfaces can be proxied, and why the handler should rethrow InvocationTargetException.getCause().

Proxy.newProxyInstance() creates an object that acts like a middleman for the interfaces you provide. Whenever you call a method, its InvocationHandler receives the proxy itself, which method you called, and the arguments you passed. The handler can add logging or checks before calling the real object. It only supports interfaces because the generated class already inherits from Proxy, and Java allows only one parent class. If the real method throws an exception, reflection wraps it in InvocationTargetException; throwing getCause() unwraps it so the caller gets the original error.

## 2. Describe the three phases of class loading (loading, linking, initialization), the situations that trigger  class initialization, and the parent delegation model: the three built-in class loaders and why delegation to the parent comes first.
loading reads the class’s bytecode and creates its Class object
linking checks the bytecode, gives static fields default values, and resolves references
initialization runs static field assignments and static blocks. Initialization happens on first active use, such as creating an instance, calling a static method, accessing a non constant static field, or using reflection that requests initialization.

## 3. Explain the roles of serialVersionUID, transient, and readResolve in Java serialization, and why deserializing data from an untrusted source is dangerous.

serialVersionUID checks version compatibility between a class and its serialized data. transient excludes a field from default serialization. readResolve() can replace a deserialized object, often to preserve a singleton. Untrusted deserialization is dangerous because malicious data can trigger code execution or exhaust resources.
