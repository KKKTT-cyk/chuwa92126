# Kubernetes Homework

## 1. Imperative commands and declarative state

“Start three copies” is a one-time command. “Keep three copies running” sets a lasting goal. The spec describes the desired state, and the status reports the latest observed state. A level-triggered controller compares the two and corrects the difference.

| Situation | Edge-triggered (acts on each event) | Level-triggered (checks current state) |
|---|---|---|
| An event is lost | The controller may miss a repair. | The next check finds the missing replica. |
| The controller restarts | It needs to replay missed events to catch up. | It reads current state and resumes. |
| An event arrives twice | It may repeat the action unless it detects duplicates. | If the replica count already matches the goal, it does nothing. |

## 2. Why coordinate through the API server?

Shared API objects let controllers work independently, give them a common view of cluster state, and centralize access control. The tradeoff is reliance on the API server for updates, which can become a bottleneck.

If two controllers read the same resourceVersion, the first valid update succeeds and changes the version. The stale update gets HTTP 409 Conflict. Its controller reads the latest object, recomputes its change, and retries. The server checks the version atomically, so clients need no shared lock. If watch history has expired (410 Gone), the client lists again and starts a new watch from the list's resourceVersion.

## 3. How do Pods, ReplicaSets, Deployments, and Services work together?

A Pod runs the application's containers. A ReplicaSet keeps the desired number of Pods alive. A Deployment manages ReplicaSets and rolls out new versions. A Service gives clients a stable address and routes traffic to matching, ready Pods as individual Pods change.

## 4. Control plane and data plane

The control plane stores cluster state, schedules Pods, and coordinates changes. The data plane consists of the worker nodes that run Pods and carry traffic. During a temporary control-plane outage, existing healthy Pods can keep serving through existing routes. New scheduling, scaling, and cluster-wide recovery wait for the control plane to return.

## 5. What happens when a client creates an object?

The API server authenticates the caller (who are you?), authorizes the action (may you create this resource?), then applies admission policies (should this particular object be changed or rejected?). If the object passes validation, the API server stores it in etcd and returns success. Controllers then act on the stored object.

## 6. What does resourceVersion do?

resourceVersion identifies a stored revision of an object. A client includes the version it read when updating the object. If another writer has already changed it, the server rejects the stale update with 409 Conflict, preventing one client's changes from silently overwriting the other's.

## 7. How do List and Watch work together?

List gives a client a snapshot and a resourceVersion. Watch starts from that version and streams later additions, updates, and deletions. The client updates its local copy as changes arrive, saving the network traffic and server work of repeatedly downloading the whole collection.
