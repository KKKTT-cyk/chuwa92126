## 1. Explain the difference between a static nested class and an inner (non-static) class. Describe the hidden reference an inner class holds, how it can cause a memory leak, and why a static nested class is usually preferred.
Static nested class does not rely on outer class, non-static class holds a hidden reference to the outer class, so it can access the outer class's method and fields, but we need to create the instance of outer class first to use the non-static class.

## 2. Explain type erasure: what the compiler does with List<String>, why new T(), new T[10] and obj instanceof List<String> are not allowed, and what a bridge method is and why the compiler generates it.
For List<String>, the runtime uses List; when you read an element as a String, the compiler inserts a cast where needed. Some generic information remains as metadata.
new T() is forbidden because the runtime does not know which class T represents or which constructor to call.
new T[10] is forbidden because arrays must know their element type at runtime, but T has been erased.
obj instanceof List<String> is forbidden because the runtime cannot distinguish a List<String> from a List<Integer>
A bridge method is a small forwarding method generated by the compiler to keep overriding working after erasure.


## 3. State the PECS rule. For List<? extends Number> and List<? super Integer>, say which operations (reading, adding) are allowed on each one and why, and explain why generics are invariant while arrays are covariant.
PECS means Producer Extends, Consumer Super. use extends when reading values and super when adding values. With List<? extends Number>, you can read elements as Number, but add only null, because the actual list might be a List<Integer> or List<Double>. With List<? super Integer>, you can add integers and null, but can only safely read elements as Object, because the actual list might contain other types. Generics are invariant, so List<Integer> is not a subtype of List<Number>; this prevents adding a Double into an integer list through a broader reference. Arrays are covariant, so Integer[] can be assigned to Number[], but arrays remember their actual element type and throw ArrayStoreException if you try to store a Double.

## 4. Describe the three retention policies (SOURCE, CLASS, RUNTIME) and what @Target, @Inherited and @Repeatable do. Which retention policy must an annotation have to be read through reflection at runtime?
SOURCE keeps an annotation only in source code and discards it during compilation
CLASS keeps it in the compiled .class file but does not expose it through runtime reflection
RUNTIME keeps it in the .class file and makes it available through reflection.

@Target specifies where an annotation may be used, such as on classes, methods, or fields.
@Inherited allows a class annotation to be inherited by subclasses; it does not apply to annotations on methods or fields, or inheritance from interfaces.
@Repeatable allows the same annotation to appear multiple times on one element, using a container annotation. To read an annotation through reflection at runtime, it must have @Retention(RetentionPolicy.RUNTIME).



## 5. List the ways to obtain a Class object. Explain what setAccessible(true) does and how the module system limits it, and why a method invoked with Method.invoke wraps an exception thrown by the target in InvocationTargetException.
You can obtain a Class object using a class literal such as String.class or int.class
Or get an existing object’s getClass(), a class name with Class.forName("java.lang.String").
setAccessible(true) asks reflection to suppress Java access checks, allowing access to otherwise inaccessible members, such as private fields or methods.
When a method called through Method.invoke() throws an exception, reflection wraps it in InvocationTargetException to distinguish an exception from the target method from a failure of reflection itself.
