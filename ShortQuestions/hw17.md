### Question 1.

- Logs store individual timestamped events and are best for explaining exactly what happened; their volume grows with event traffic.

- Metrics store timesteamped numerical samples identified by a name and label set; storage grows mainly with the number of label combinations and collection frequency.

- Trances store linked spans showing a request's causal path; volume grows with request traffic and spans per request.

Metrics detect problems, traces locate them, and logs explain the details.

The telemetry pipeline is itself a distributed system because many producers continuously write through collectors, buffers, and storage components that can fail independently. Its workload is heavily write-dominated, with comparatively fewer dashboard and investigation reads, so it needs batching, compression, buffering, and overload isolation.

### Question 2.

A full-text inverted index pays more at write time to tokenize records, build indexes, and merge segments, making selective arbitrary text searches fast. High-cardinality values increase index cost, while uncontrolled field names can cause mapping explosion.

A label-index system indexes selected labels and store log contents in compressed chunks. Writes and storage are cheaper, but text searches must scan the selected chunks. High-cardinaliry labels create too many streams and small chunks.

For very high volume with mostly "this service, last 15 minutes" queries, I would choose label indexing with compressed object-storage chunks, because the query filters keep scans small while reducing the cost paid for every write.

### Question 3.

Pull means the collector discovers targets and scrapes them on its own schedule. It controls collection frequency and gets an explicit failure signal when a scrape fails, but it needs network access to each target and may miss short-lived jobs.

Push means producers send measurements to a known receiver. It works well for batch jobs and networks that allow outbound connections but block inboud access. Missing data is ambiguous without heartbeats, and faulty producers can overwhelm the receiver, so rate limits, quotas, and bounded queues are important.

Pull gives stronger control over collection load, although oversized responses and high cardinality still need limits. A practical design can scrape long-running services locally and push batches to a central backend.
