## 1. Explain what a cross-cutting concern is, and use the OrderService example from class to explain "tangling" and "scattering".
A cross-cutting concern is functionality needed across multiple parts of an application, such as logging, security, execution time counting. In the orderService, those things are around the main business logic codes.
Tangling means those other codes mixed with the main business logic which makes the code hard to understand and maintain,
Scattering means similar codes like logging may need to write in different services method.

## 2. Define aspect, join point, pointcut, advice, target and proxy, and state what a join point always is in Spring AOP.

Aspect is the module that contains all those corss-cutting concern.
Join point is a point where to apply advice during a method execution.
Pointcut is the expression that selects which join points advice applies for.
Advice is the timing to apply at the select join points.
Target is the he original business object being enhanced by advice.
Proxy is the object Spring creates to intercept calls and apply advice before delegating to the target.

## 4. Describe three mistakes that are easy to make inside an @Around advice and the effect of each one.
Calling proceed() but not returning its result: The caller receives whatever the advice returns, potentially null. Returning null for a non-void primitive return type causes an error.

Catching an exception without rethrowing it: The failure is hidden from the caller. If an outer transaction interceptor never sees the exception and the transaction is not already marked rollback-only, it may commit instead of rolling back.

Forgetting to call proceed(): The target method never executes. This is a mistake unless intentionally skipping execution, such as returning a cached value.




## 5. Explain what each pointcut expression matches: execution(* com.example.orders.service.*.* (..)), execution(* com.example.orders..*.*(..)), execution(* *(Long, ..)) and @annotation(com.example.orders.aop.LogExecutionTime).
execution(* com.example.orders.service.*.*(..)): Methods in any class directly inside com.example.orders.service, with any return type, name, and parameters. Excludes subpackages.

execution(* com.example.orders..*.*(..)): Methods in any class inside com.example.orders or any of its subpackages, with any return type, name, and parameters.

execution(* *(Long, ..)): Methods with any return type and name whose first declared parameter is Long, followed by zero or more additional parameters. Long is the wrapper type, not primitive long.

## 6. Explain how Spring AOP applies advice through proxies, at which step of the bean lifecycle the proxy is created, and how you can check that an injected bean is a proxy.
Spring AOP wraps eligible beans in JDK dynamic proxies or CGLIB proxies. Other beans receive the proxy reference. When a method is called through it, the proxy executes the matching advice chain, which can run logic before, after, or around the target method.




## 7. Explain why calling a method annotated with @LogExecutionTime or @Transactional from another method of the same class skips the advice, and describe two ways to fix it.
Because it is self invocation calling a method from another method of the same class. First, we can move the method to another service or bean, inject that service and call its method.
Second, we can use enable proxy exposure with @EnableAspectJAutoProxy(exposeProxy = true).



## 8. State the default rollback rules of @Transactional, and describe three situations in which a @Transactional method does not roll back even though something went wrong.
By default, @Transactional rolls back when an unhandled RuntimeException or Error escapes the method. Checked exceptions do not trigger rollback by default.
Three situations where something goes wrong without automatic rollback are:
1. A checked exception is thrown, such as IOException. Spring normally commits despite the exception. Configure rollbackFor = Exception.class if checked exceptions should trigger rollback.
2. The method catches and swallows the exception. If it returns normally, the transaction interceptor sees no failure and may commit. Rethrow the exception when the operation must fail. However, if the transaction is already marked rollback-only, swallowing the exception cannot make it commit.
3. The method is called from another method of the same class. Self-invocation bypasses the proxy, so its @Transactional advice does not run and does not start a transaction.




## 9. SecurityAspect has @Order(1) and TimingAspect has @Order(2), and both use @Around on the same method. Describe the order in which their code runs. Then compare Spring AOP with AspectJ in terms of weaving and the join points each one supports.
1. SecurityAspect’s code before proceed().
2. TimingAspect’s code before proceed().
3. The target method.
4. TimingAspect’s code after proceed().
5. SecurityAspect’s code after proceed().
Thus, higher precedence means first in, last out. If SecurityAspect rejects the call without proceeding, neither TimingAspect nor the target runs.
