1. Cross-cutting concern is logic that not belongs to business classes' core job but many classes need and need to be
extracted and managed centrally, it has six different types which are logging, metrics, transactions, security, caching
and retry. 
The tangling and scattering problem can be explained with the example of a class OrderService, there is a method 
placeOrder() that only contains one line core logic code: createAndSave(request), and other codes are about logging, 
metrics and security, which could be extracted and managed centrally, is tangling problem, and other methods also have
many same non-core code about logging, metrics and security. The same non-core code which scattered in different methods
is called scattering problem.
2. An aspect is a module that holds one crossing-cutting concern.
A join point is a point in execution where an aspect can plug in and in Spring AOP this is always a method execution.
A pointcut is an expression that selects join points.
Advice is the code to run at the selected join points and when(before, after, around) to run the code.
A target is the original object that to be advised.
A proxy is the object Spring creates around the target to apply the advice.
In Spring AOP, a join point is always a method execution.
3. @Before runs before the method, and will not change the return value and only prevent the method from running by
throwing an exception.
@AfterReturning runs after a normal return which is in the try block and will not change the return value and not prevent
the method from running.
@AfterThrowing runs after an exception which is in the catch block, and will not change the return value and not prevent
the method from running.
@After always runs and in the finally block, and will change the return result and can prevent the method from running.
4. Mistakes in @Around:
Mistake 1: Calling pjp.proceed() without returning its value, and under this mistake, the caller always receives null,
for a primitive return type Spring throws AopInvocationException.
Mistake 2: Catching Throwable and not rethrowing, under this mistake, exceptions vanish silently, and if this aspect 
runs inside the transaction advice, @Transactional will not roll back.
Mistake 3: Forgetting pjp.proceed(), under this mistake, the target will never run.
5. execution(* com.example.orders.service.*.*(..)) matches every method of every class directly in service.
execution(* com.example.orders..*.*(..)), execution(* *(Long, ..)) matches every method in orders and all sub-packages
and with methods have exactly one Long parameter.
@annotation(com.example.orders.aop.LogExecutionTime) matches methods annotated with @LogExecutionTime.
6. Spring AOP uses proxies to intercept method calls and executed advice before, after or around the target method.
The proxy is created by a BeanPostProcessor, during the postProcessAfterInitialization() phase of the bean lifecycle.
We can check whether an injected bean is a proxy bean using AopUtils.isAopProxy(bean).
7. Spring works through a proxy. When a method calls another method in the same class using this, the call bypasses the
proxy, so advice such as @LogExecutionTime or @Transactional is not applied.
Two ways to fix the problem:
1)Move the annotated method to another Spring bean and call it through the injected bean.
2)Inject the bean's proxy, like using @Lazy, and call the annotated method through that proxy instead of this.
8. By default, @Transactional rolls back on unchecked exceptions, error, but not on checked exceptions. 
Three situations where rollbacks may happen:
1)The exception is caught and swallowed inside the method, the transaction interceptor sees a normal return.
2)A checked exception is thrown without a matching rollback rule.
3)The method is called within the same class, bypassing the Spring proxy, and the @Transactional annotation is not applied.
9. Order: SecurityAspect before->Timing before-> target method->Timing after->Security after.
Spring AOP uses runtime proxies and supports only method execution join points on Spring beans.
While AspectJ uses compile-tile, post-compile, or load-time weaving and support more joint points, including method calls
and executions, constructor calls and execution, and field access or modification. It can also advise objects that are 
not managed by Spring.
