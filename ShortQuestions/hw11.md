## Question1: What is Kafka? What problems does it typically solve?
Apache Kafka is a distributed event-streaming platform designed to publish, store, and process large volumes of messages in real time.

Kafka is commonly used to solve several problems:
- Asynchronous communication: Enables services to communicate without waiting for each other.
- System decoupling: Producers and consumers can operate independently.
- High-throughput data processing: Handles large volumes of messages efficiently.
- Scalability: Distributes workloads across multiple brokers and partitions.
- Fault tolerance: Replicates data across brokers to reduce the risk of data loss.
- Event-driven architecture: Enables systems to react to events in real time.

## Question2: What is a Message (Record)? What information can a Kafka message contain?
A Kafka message, also called a record, is the basic unit of data stored in Kafka.

A Kafka record typically contains:
- Key: An optional identifier used to influence partition selection.
- Value: The actual message content, such as JSON, text, or binary data.
- Timestamp: Indicates when the record was created or appended to Kafka.
- Headers: Optional metadata stored as key-value pairs.

## Question3:What is a Producer? What responsibilities does it have in Kafka?
A Kafka Producer is an application or component responsible for publishing messages to Kafka topics.

Its main responsibilities include:
- Creating and sending messages to Kafka.
- Selecting the destination topic and partition.
- Serializing message keys and values.
- Batching and compressing messages for efficiency.
- Handling delivery acknowledgments and retrying failed requests when configured.

## Question4:What is a Consumer? What responsibilities does it have in Kafka?
A Kafka Consumer is an application or component responsible for reading and processing messages from Kafka topics.

Its main responsibilities include:
- Subscribing to one or more Kafka topics.
- Reading messages from assigned partitions.
- Deserializing and processing messages.
- Tracking consumption progress using offsets.
- Committing offsets to record its processing progress when appropriate.

## Question5:What is a Topic? Why does Kafka use Topics to categorize messages?
A Kafka Topic is a logical category or named stream where related messages are published and stored.

Topics provide several advantages:
1. Organization: Different event types can be managed separately.
2. Decoupling: Producers and consumers communicate through topics instead of directly.
3. Independent configuration: Different topics can have their own retention, partitioning, and replication settings.
4. Multiple consumers: Different consumer groups can independently process messages from the same topic.

## Question6:What is a Broker? Why can a Kafka cluster contain multiple Brokers?
A Kafka Broker is a server that stores Kafka messages and handles requests from producers and consumers.
A broker is responsible for storing partition data, accepting writes, serving reads, and participating in replication.

A Kafka cluster can contain multiple brokers to provide:
- Scalability: Distribute partitions and workload across multiple servers.
- Fault tolerance: Replicate partition data so another broker can take over if one fails.
- High availability: Keep services operating when individual brokers become unavailable.
- Load distribution: Avoid concentrating all storage and network traffic on one server.

## Question7:What is a Partition? Why might a Topic need multiple Partitions?
A Partition is an ordered, append-only log that stores a subset of a topic's messages.

A topic may contain multiple partitions for several reasons:
- Parallel processing: Multiple consumers within the same consumer group can process different partitions simultaneously.
- Higher throughput: Producers and consumers can distribute work across partitions.
- Scalability: Partitions can be distributed among different brokers.
- Workload distribution: Partitioning prevents a topic from depending on a single partition for all messages.

## Question8:What is an Offset? Is it a global message identifier or a position within a Partition?
An Offset is a numerical position assigned to a record within a specific Kafka partition.

Offsets are maintained independently for each partition, rather than globally across an entire topic.
Offsets allow consumers to track their positions and resume reading from a specific location.
Therefore, an offset represents a record's position within a particular partition, not a globally unique message number.

## Question9:What is a Consumer Group? How do multiple Consumers within the same group divide the work?
A Consumer Group is a collection of Kafka consumers that cooperate to process messages from subscribed topics.

Kafka assigns partitions among consumers in the same group.
For standard Kafka consumer groups:
- Each partition is assigned to at most one consumer within a group at a time.
- A consumer can be assigned multiple partitions.
- When consumers join or leave the group, Kafka may redistribute partition assignments through rebalancing.

Each consumer processes messages from its assigned partition independently.

## Question10:What is a Message Key? How does the Key affect which Partition receives a message?
A Message Key is an optional field associated with a Kafka record that can be used to determine which partition receives it.

With a common key-based partitioning strategy, Kafka uses a hash of the serialized key to select a partition.
Records with the same key generally go to the same partition, provided the partition count and partitioning strategy remain unchanged.

## Question11:What is the difference between a Topic and a Partition? Describe their relationship in one sentence.
A Topic is a logical stream that categorizes messages, while a Partition is a physical log that stores a subset of those messages.
A Kafka Topic consists of one or more Partitions that distribute and store its messages for scalability and parallel processing.

## Question12:What is the difference between a Broker and a Kafka Cluster? Is a single Broker equivalent to a Kafka Cluster?
A Broker is an individual Kafka server responsible for storing and serving data.
A Kafka Cluster is a group of one or more brokers working together as a distributed system.

Technically, a Kafka cluster can consist of just one broker, especially in development or testing environments.

## Question13:Do Producers and Consumers need to know each other's identities? Explain why.
No. Kafka producers and consumers do not need to know each other's identities.
Kafka uses a publish-subscribe model in which producers publish messages to topics, and consumers independently subscribe to those topics.

## Question14:Is an Offset determined by the Producer? Why must Consumers track their consumption positions?
No. A producer does not determine the offset of a message.
The Kafka broker assigns an offset when the message is appended to a partition's log.
Consumers use offsets to track how far they have progressed through each assigned partition.

Tracking offsets is important for several reasons:
- Failure recovery: Consumers can resume processing after a crash or restart.
- Avoiding unnecessary reprocessing: Committed offsets help identify which messages have already been handled.
- Message replay: Consumers can seek to earlier offsets to reprocess retained messages.
- Independent consumption: Different consumer groups maintain independent consumption progress.
  Kafka typically stores committed consumer group offsets in an internal topic named __consumer_offsets.

## Question15:Is the statement "Kafka guarantees strict ordering of all messages within an entire Topic" correct? Explain the scope of Kafka's ordering guarantee.
No, the statement is incorrect.
Kafka guarantees the order of records within a single partition's log, but it does not guarantee a global ordering across multiple partitions.

## Question16:If a Topic has 3 Partitions and a Consumer Group has 5 Consumers, how many Consumers can consume messages simultaneously? What happens to the remaining Consumers?
At most 3 consumers can actively consume messages from this topic at the same time within that consumer group.
This is because each partition can be assigned to only one consumer within the same group under the standard consumer group model.
Consumers 4 and 5 remain idle for this topic because there are no additional partitions available.
If an active consumer fails or leaves the group, Kafka can rebalance the partitions and assign the available work to another consumer.

## Question17:If two different Consumer Groups subscribe to the same Topic, will they compete for messages? Explain which messages each group can see.
No. Two different consumer groups do not compete for messages.

Each consumer group maintains its own offset positions and independently reads messages from the same topic.
