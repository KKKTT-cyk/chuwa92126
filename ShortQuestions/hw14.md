# Homework 14 - Data Access

## 1. What is ORM?

ORM stands for Object-Relational Mapping. It maps Java objects to relational database data, so we can work with objects instead of writing SQL for every operation.

In a simple mapping:

- A Java entity class maps to a database table, such as `Student` to `students`.
- A Java object represents one row, such as one student.
- A persistent Java field maps to a column, such as `name` to the `name` column.

## 2. What is the difference between JPA and Hibernate?

JPA, now called Jakarta Persistence, is a specification. It defines standard annotations and APIs for mapping and persisting Java objects.

Hibernate is an ORM framework that implements JPA. It performs the actual mapping and generates SQL. JPA defines the rules; Hibernate provides an implementation of those rules.

## 3. What problem does Spring Data JPA solve?

Spring Data JPA reduces repetitive repository code for common database operations.

```java
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```

Here, `Student` is the entity type and `Long` is its ID type. Spring creates a repository proxy at runtime and connects it to a provided implementation, so we can use inherited methods such as `save()` and `findById()` without implementing them ourselves.

Spring Data JPA uses JPA APIs, and Hibernate can be the JPA provider underneath. For example, `save()` uses the JPA `EntityManager` to persist or merge an entity; SQL may run later when changes are flushed. `findById()` returns an `Optional<Student>`.

## 4. What is an Entity?

An entity is a Java class whose instances represent persistent data with an identity.

- `@Entity`: marks the class as a JPA entity.
- `@Table(name = "students")`: maps the entity to the `students` table.
- `@Id`: marks the primary key field.
- `@GeneratedValue`: specifies that the primary key value is generated using a generation strategy.

## 5. Why does an Entity need a primary key?

A primary key uniquely identifies a row. JPA uses the field marked with `@Id` to identify and track the entity, including which row to update or delete.

A new entity with a generated `Long` ID may initially have a `null` ID because it has not been assigned yet. The generation strategy determines when the value becomes available: for example, a sequence can supply it before insertion, while an identity column generates it during insertion.

## 6. Why use Enrollment between Student and Course?

Students and courses have a many-to-many relationship. A simple `@ManyToMany` can represent the links, but it does not give each link its own entity for storing extra information.

An `Enrollment` represents one student taking one course. It has a `@ManyToOne` relationship to `Student` and another to `Course`.

Fields such as `enrollmentDate`, `grade`, or `status` belong in `Enrollment`, because they describe a particular student's enrollment in a particular course, not the student or course alone.

## 7. What is the owning side?

```java
public class Enrollment {
    @ManyToOne
    @JoinColumn(name = "student_id")
    private Student student;
}
```

The `Enrollment.student` association is the owning side. The `student_id` column in the enrollment table is the foreign key referencing the student's primary key.

The owning side determines the relationship value written to the database. Setting `enrollment.setStudent(student)` changes the association that JPA persists. In a bidirectional relationship, we should also keep the student's enrollment collection consistent in memory.

## 8. What does mappedBy = "student" mean?

In `Student`:

```java
@OneToMany(mappedBy = "student")
private List<Enrollment> enrollments;
```

This says that `Student.enrollments` is the inverse side, and the relationship is owned by the `student` field in `Enrollment`.

`mappedBy` refers to the Java relationship field or property, not a database column. Therefore, it uses `"student"`. The physical foreign key column name, `"student_id"`, is specified separately by `@JoinColumn` on the owning side.

## 9. What is the difference between LAZY and EAGER?

- **LAZY:** asks the provider to delay loading related data until it is accessed. For example, load a student first and load enrollments when needed. In JPA, LAZY is a hint.
- **EAGER:** requires related data to be loaded as part of fetching the entity, even if the application does not use it. This does not necessarily mean one SQL query.

Making every relationship EAGER can load unnecessary data, increase memory usage, and cause extra queries. We should fetch the relationships needed for each use case. Lazy data should be accessed while the persistence context is available, usually within the service transaction.

## 10. How does a request reach the database?

Example: find enrollments for student `123`.

```text
HTTP Request -> Controller -> Service -> Repository
             -> Hibernate -> JDBC -> Database
```

1. **HTTP Request:** the client sends `GET /students/123/enrollments`.
2. **Controller:** reads `studentId` from the URL and calls the service.
3. **Service:** applies business rules and manages the transaction, then asks the repository for the student's enrollments.
4. **Repository:** provides a method such as `findByStudent_Id(123L)`. Spring Data JPA derives the query using the `student.id` property path and delegates through JPA.
5. **Hibernate:** translates the entity query into SQL and maps returned rows to `Enrollment` objects.
6. **JDBC:** provides the database access API; the JDBC driver sends SQL and parameters to the database and reads the results.
7. **Database:** executes the SQL and returns matching rows.

For this mapping, the SQL would be similar to:

```sql
SELECT * FROM enrollments WHERE student_id = 123;
```

The results travel back through the layers. The service can convert them into response DTOs, and the controller returns the response as JSON.
