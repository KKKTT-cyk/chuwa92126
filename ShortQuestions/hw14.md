#### Conceptual Questions

1. **Explain how java.lang.reflect.Proxy works: what Proxy.newProxyInstance generates at runtime, what an InvocationHandler receives on every call, why only interfaces can be proxied, and why the handler should rethrow InvocationTargetException.getCause().**

   Proxy.newProxyInstance() creates an instance of a runtime proxy class that implements the supplied interfaces. The generated class extends java.lang.reflect.Proxy, and its interface method calls are routed to an InvocationHandler. For each intercepted call, the handler receives the proxy object, a Method describing the invoked method, and an Object[] containing the arguments, which can be null for a method with no arguments. Calls to equals(), hashCode() and toString() also go through the handler. The handler can perform extra work, such as logging or permission checks, before delegating to a real object and returning its result. JDK dynamic proxies implement interfaces rather than subclassing concrete application classes; the generated class already extends Proxy, and Java does not support multiple class inheritance. When delegation uses Method.invoke(), an exception thrown by the target is wrapped in InvocationTargetException. The handler should rethrow getCause() so callers receive the original failure instead of the reflection wrapper. If the original exception is checked and is not declared by the interface method, the proxy wraps it in UndeclaredThrowableException.

2. **Describe the three phases of class loading (loading, linking, initialization), the situations that trigger class initialization, and the parent delegation model: the three built-in class loaders and why delegation to the parent comes first.**

   Loading finds a class's bytecode, defines the class and creates its Class object. Linking includes verification, which checks the bytecode; preparation, which allocates static fields and gives them default values; and resolution, which converts symbolic references to runtime references and may occur lazily. Initialization executes static field initializers and static initializer blocks in their declared order, with JVM synchronization to prevent concurrent initialization of the same class. Initialization is triggered by active use, such as creating an instance, calling a static method, reading or writing a non-constant static field, reflective operations that require initialization, or running the class's main method. Class.forName(name) initializes the class by default, and initializing a class also initializes its superclass first. A class literal, creating an array of that class, reading an inlined compile-time constant, ClassLoader.loadClass(), or Class.forName(name, false, loader) does not itself initialize the class. Accessing an inherited static field through a subclass initializes the class that declares the field, not necessarily the subclass.

   The three built-in loaders are the bootstrap class loader, which loads core classes such as java.lang.String; the platform class loader, which loads additional Java platform classes; and the application class loader, which normally loads application classes from the class path. In the usual parent delegation model, a loader first checks whether it has already loaded the class, then asks its parent before trying to find the class itself. The application loader delegates to the platform loader, which delegates to the bootstrap loader. Parent-first delegation helps prevent application classes from replacing core platform classes and allows child loaders to share the same parent-defined types. This matters because a class's identity depends on both its binary name and its defining class loader. Custom loaders can use different delegation policies when isolation is required.

3. **Explain the roles of serialVersionUID, transient, and readResolve in Java serialization, and why deserializing data from an untrusted source is dangerous.**

   serialVersionUID is a version identifier used to check compatibility between a serialized ordinary Serializable class and the local class definition. A mismatch normally causes InvalidClassException. Declaring it explicitly avoids relying on a compiler-derived value that can change after class modifications, but using the same identifier does not make every structural change compatible. transient excludes an instance field from default serialization, which is useful for derived state, caches or sensitive values. After ordinary deserialization, a transient field has its default value unless custom restoration code sets it; custom serialization can still explicitly write transient data. readResolve() lets a deserialized object be replaced with another object before it is returned, such as returning the existing instance of a singleton. Deserializing untrusted data is dangerous because the stream controls the object graph and can trigger behavior in methods such as readObject() and readResolve(). Malicious object graphs can exploit chains of library methods to execute code, violate invariants or exhaust resources. Avoid native Java deserialization of untrusted input; when it is unavoidable, use strict class and resource filters and validate the reconstructed state.
