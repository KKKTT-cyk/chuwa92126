
# Java Advanced Syntax Homework — Solutions

## 1. Static Nested Class vs Inner Class

A static nested class is declared with the `static` keyword, while an inner class is a non-static class declared inside another class.

### Static Nested Class

```java
class Outer {
    static class Nested {
        void display() {
            System.out.println("Static nested class");
        }
    }
}
```

Usage:

```java
Outer.Nested obj = new Outer.Nested();
obj.display();
```

A static nested class does not require an instance of the outer class. It cannot directly access non-static members of the outer class without an object reference.

### Inner Class

```java
class Outer {
    private String message = "Hello";

    class Inner {
        void display() {
            System.out.println(message);
        }
    }
}
```

Usage:

```java
Outer outer = new Outer();
Outer.Inner inner = outer.new Inner();
inner.display();
```

An inner class requires an instance of the outer class and can directly access its instance members, including private fields.

### Hidden Reference

An inner class instance holds an enclosing-instance reference to its outer class object.

For example:

```java
class Outer {
    private byte[] data = new byte[10_000_000];

    class Inner {
        void execute() {
            System.out.println("Executing");
        }
    }
}
```

If an `Inner` object remains reachable after the outer object is no longer needed, its reference to `Outer` may prevent the outer object and its large `data` array from being garbage-collected.

This can cause a memory leak when objects are retained unintentionally.

### Why Static Nested Classes Are Usually Preferred

Static nested classes are usually preferred when access to an enclosing instance is unnecessary because:

1. They do not hold an implicit reference to an outer instance.
2. They reduce the risk of unintended object retention.
3. They make dependencies more explicit.
4. They can be instantiated independently.

Use an inner class when the nested object genuinely needs access to a specific outer instance.

## 2. Type Erasure in Java Generics

Type erasure is the process by which the Java compiler removes most generic type information during compilation.

Generics provide compile-time type safety, but most generic type parameters are not preserved as runtime type arguments.

### Example: List<String>

```java
List<String> names = new ArrayList<>();
names.add("Alice");

String name = names.get(0);
```

After type erasure, the compiler treats the generic operations approximately like:

```java
List names = new ArrayList();
names.add("Alice");

String name = (String) names.get(0);
```

The compiler inserts casts where necessary and checks type correctness at compile time.

Generic type parameters are replaced by their upper bounds, or `Object` if no explicit bound exists.

### Why new T() Is Not Allowed

```java
class Box<T> {
    T create() {
        return new T(); // Compilation error
    }
}
```

The compiler cannot instantiate `T` because its concrete type is unavailable at runtime.

A possible solution is to provide a factory:

```java
class Box<T> {
    private final Supplier<T> factory;

    Box(Supplier<T> factory) {
        this.factory = factory;
    }

    T create() {
        return factory.get();
    }
}
```

### Why new T[10] Is Not Allowed

```java
class Box<T> {
    T[] items = new T[10]; // Compilation error
}
```

Java arrays preserve their component type at runtime, while generic type parameters are erased.

Creating a generic array directly would conflict with Java's runtime array type checks.

A possible alternative is:

```java
List<T> items = new ArrayList<>();
```

### Why instanceof List<String> Is Not Allowed

```java
if (obj instanceof List<String>) {
    // Compilation error
}
```

At runtime, Java cannot distinguish `List<String>` from `List<Integer>` using `instanceof`.

Instead:

```java
if (obj instanceof List<?>) {
    System.out.println("It is a List");
}
```

### Bridge Methods

A bridge method is a synthetic method generated by the compiler to preserve polymorphism after type erasure.

Example:

```java
class Parent<T> {
    T get() {
        return null;
    }
}

class Child extends Parent<String> {
    @Override
    String get() {
        return "Hello";
    }
}
```

After erasure, the parent's method has a return type of `Object`, while the child's method returns `String`.

The compiler generates a bridge method approximately equivalent to:

```java
Object get() {
    return get();
}
```

Conceptually, the bridge method has the erased `Object` return type and delegates to the more specific `String get()` implementation.

This preserves correct overriding and polymorphic behavior after type erasure.

## 3. PECS Rule and Generic Variance

PECS stands for:

**Producer Extends, Consumer Super.**

- Use `? extends T` when a collection produces values that you want to read.
- Use `? super T` when a collection consumes values that you want to add.

### List<? extends Number>

```java
List<? extends Number> numbers;
```

The list may actually refer to:

```java
List<Integer>
List<Double>
List<Float>
```

Reading is allowed:

```java
Number value = numbers.get(0);
```

Adding non-null values is not allowed:

```java
numbers.add(10);   // Compilation error
numbers.add(3.14); // Compilation error
```

The compiler does not know the exact subtype of `Number` used by the list.

However, adding `null` is allowed.

### List<? super Integer>

```java
List<? super Integer> numbers;
```

The list may refer to:

```java
List<Integer>
List<Number>
List<Object>
```

Adding an `Integer` is allowed:

```java
numbers.add(10);
numbers.add(Integer.valueOf(20));
```

Reading is allowed, but the result can only be safely treated as `Object` without additional type information:

```java
Object value = numbers.get(0);
```

This is because the actual list might be a `List<Object>` or `List<Number>`.

### Comparison

| Operation | List<? extends Number> | List<? super Integer> |
|---|---|---|
| Read as Number | Yes | Not guaranteed |
| Read as Object | Yes | Yes |
| Add Integer | No | Yes |
| Add Double | No | No |
| Add null | Yes | Yes |

### Why Generics Are Invariant

Java generics are invariant.

This means:

```java
List<Integer>
```

is not a subtype of:

```java
List<Number>
```

Even though `Integer` is a subtype of `Number`.

If Java allowed this:

```java
List<Integer> integers = new ArrayList<>();
List<Number> numbers = integers;

numbers.add(3.14);
```

a `Double` could be inserted into a list intended to contain only `Integer` objects.

Java prevents this at compile time.

### Why Arrays Are Covariant

Java arrays are covariant.

For example:

```java
Integer[] integers = new Integer[3];
Number[] numbers = integers;
```

This assignment is allowed.

However:

```java
numbers[0] = 3.14;
```

throws `ArrayStoreException` at runtime because the actual array is an `Integer[]`.

Generics prevent this kind of unsafe assignment at compile time, while arrays rely on runtime type checking.

## 4. Annotation Retention Policies and Meta-Annotations

Java supports three annotation retention policies.

### SOURCE

```java
@Retention(RetentionPolicy.SOURCE)
@interface SourceAnnotation {}
```

The annotation exists only in source code and is discarded by the compiler.

Typical uses include compile-time checks and source-level tooling.

### CLASS

```java
@Retention(RetentionPolicy.CLASS)
@interface ClassAnnotation {}
```

The annotation is stored in the compiled `.class` file but is not available through ordinary runtime reflection.

`CLASS` is the default retention policy.

### RUNTIME

```java
@Retention(RetentionPolicy.RUNTIME)
@interface RuntimeAnnotation {}
```

The annotation is stored in the compiled class file and remains available through reflection at runtime.

Example:

```java
@RuntimeAnnotation
class Example {}
```

Reading the annotation:

```java
boolean present =
    Example.class.isAnnotationPresent(
        RuntimeAnnotation.class
    );
```

### @Target

`@Target` specifies where an annotation can be applied.

Example:

```java
@Target(ElementType.FIELD)
@interface NotNull {}
```

This annotation can be applied to fields.

Other targets include `TYPE`, `METHOD`, `PARAMETER`, and `CONSTRUCTOR`.

### @Inherited

`@Inherited` allows subclasses to inherit certain annotations declared on a superclass.

Example:

```java
@Inherited
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Entity {}
```

If a superclass has `@Entity`, a subclass may inherit that annotation when queried through supported class-level reflection APIs.

`@Inherited` only applies to annotations on classes. It does not cause field or method annotations to be inherited.

### @Repeatable

`@Repeatable` allows the same annotation to appear multiple times on one declaration.

Example:

```java
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@Repeatable(Tags.class)
@interface Tag {
    String value();
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface Tags {
    Tag[] value();
}
```

Usage:

```java
@Tag("backend")
@Tag("java")
class Application {}
```

### Which Retention Policy Supports Runtime Reflection?

**RUNTIME** is required for annotations to be retrieved through reflection at runtime.

## 5. Reflection and Class Objects

Reflection allows Java programs to inspect classes, fields, constructors, methods, and annotations at runtime.

### Ways to Obtain a Class Object

**1. Using .class**

```java
Class<String> clazz = String.class;
```

This works when the type is known at compile time.

**2. Using getClass()**

```java
String value = "Hello";
Class<?> clazz = value.getClass();
```

This obtains the runtime class of an existing object.

**3. Using Class.forName()**

```java
Class<?> clazz = Class.forName("java.lang.String");
```

This loads or locates a class by its fully qualified name.

**4. Using a ClassLoader**

```java
ClassLoader loader =
    Thread.currentThread().getContextClassLoader();

Class<?> clazz =
    loader.loadClass("java.lang.String");
```

This is useful for dynamic class loading.

### What Does setAccessible(true) Do?

`setAccessible(true)` requests that Java suppress normal Java language access checks for a reflected member.

Example:

```java
class Person {
    private String name = "Alice";
}
```

Accessing the private field:

```java
Person person = new Person();

Field field =
    Person.class.getDeclaredField("name");

field.setAccessible(true);

String value = (String) field.get(person);

System.out.println(value);
```

Output:

```text
Alice
```

### How the Java Module System Limits Reflection

Since Java 9, the Java Platform Module System (JPMS) provides stronger encapsulation.

Calling `setAccessible(true)` does not guarantee access to private members in another module.

For deep reflection across module boundaries, the target package generally must be opened to the calling module.

Example:

```java
opens com.example.model to my.framework;
```

Alternatively, a JVM option can open a package:

```text
--add-opens module.name/package.name=ALL-UNNAMED
```

If access cannot be enabled, Java may throw `InaccessibleObjectException`.

### Why Method.invoke Uses InvocationTargetException

Consider:

```java
class Example {
    public void execute() {
        throw new IllegalStateException("Failed");
    }
}
```

Invoking the method through reflection:

```java
Example obj = new Example();

Method method =
    Example.class.getMethod("execute");

try {
    method.invoke(obj);
} catch (InvocationTargetException e) {
    Throwable original = e.getCause();
    System.out.println(original.getMessage());
}
```

Output:

```text
Failed
```

`Method.invoke()` wraps exceptions thrown by the invoked target method in `InvocationTargetException`.

This separates exceptions caused by the target method from reflection-related errors, such as illegal access or invalid arguments.

The original exception can be retrieved using:

```java
e.getCause()
```

## 6. Complete Validator.validate Using Reflection

### Requirements

The validator must:

1. Throw `IllegalArgumentException` if the target is null.
2. Inspect fields declared in the target's class and its superclasses.
3. Ignore static fields.
4. Access private fields through reflection.
5. Check every applicable validation annotation.
6. Report all violations, including multiple violations on one field.
7. Sort the resulting messages alphabetically.

Validation rules:

- `@NotNull`: Reject null values.
- `@NotBlank`: Reject null, empty, or whitespace-only strings.
- `@Range`: Reject int or long values outside the inclusive range.
- Null wrapper values are not rejected by `@Range` alone.

### Complete Java Solution

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

import java.lang.reflect.Field;
import java.lang.reflect.Modifier;

import java.util.ArrayList;
import java.util.Collections;
import java.util.List;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotNull {
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotBlank {
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    long min();
    long max();
}

class Person {

    @NotBlank
    private String name;

    @NotNull
    @Range(min = 0, max = 150)
    private Integer age;

    Person(String name, Integer age) {
        this.name = name;
        this.age = age;
    }
}

public final class Validator {

    private Validator() {
    }

    public static List<String> validate(Object target) {

        // 1. Reject null target.
        if (target == null) {
            throw new IllegalArgumentException(
                "Target must not be null"
            );
        }

        List<String> violations = new ArrayList<>();

        // 2. Start with the object's runtime class.
        Class<?> clazz = target.getClass();

        // 3. Inspect the class and its superclasses.
        while (clazz != null && clazz != Object.class) {

            for (Field field : clazz.getDeclaredFields()) {

                // 4. Ignore static fields.
                if (Modifier.isStatic(field.getModifiers())) {
                    continue;
                }

                // 5. Allow access to private fields.
                try {
                    field.setAccessible(true);

                    Object value = field.get(target);
                    String fieldName = field.getName();

                    // 6. Check @NotNull.
                    if (field.isAnnotationPresent(NotNull.class)) {

                        if (value == null) {
                            violations.add(
                                fieldName + ": must not be null"
                            );
                        }
                    }

                    // 7. Check @NotBlank.
                    if (field.isAnnotationPresent(NotBlank.class)) {

                        if (value == null ||
                            ((String) value).isBlank()) {

                            violations.add(
                                fieldName + ": must not be blank"
                            );
                        }
                    }

                    // 8. Check @Range.
                    Range range =
                        field.getAnnotation(Range.class);

                    if (range != null && value != null) {

                        long number = ((Number) value).longValue();

                        if (number < range.min() ||
                            number > range.max()) {

                            violations.add(
                                fieldName +
                                ": must be between " +
                                range.min() +
                                " and " +
                                range.max()
                            );
                        }
                    }

                } catch (IllegalAccessException e) {

                    throw new IllegalStateException(
                        "Cannot access field: " +
                        field.getName(),
                        e
                    );
                }
            }

            // 9. Move to the superclass.
            clazz = clazz.getSuperclass();
        }

        // 10. Sort violations alphabetically.
        Collections.sort(violations);

        // 11. Return all violations.
        return violations;
    }
}
```

### Explanation of the Implementation

**Step 1: Validate the input**

```java
if (target == null) {
    throw new IllegalArgumentException(
        "Target must not be null"
    );
}
```

The homework requires an `IllegalArgumentException` when the target is null.

**Step 2: Obtain the runtime class**

```java
Class<?> clazz = target.getClass();
```

`getClass()` returns the actual runtime class of the object.

**Step 3: Traverse the class hierarchy**

```java
while (clazz != null && clazz != Object.class) {
    // Validate fields.

    clazz = clazz.getSuperclass();
}
```

This ensures that fields declared in superclasses are also checked.

The traversal stops before `Object.class`.

**Step 4: Obtain declared fields**

```java
for (Field field : clazz.getDeclaredFields()) {
```

`getDeclaredFields()` returns fields declared directly in the current class, including private fields.

**Step 5: Ignore static fields**

```java
if (Modifier.isStatic(field.getModifiers())) {
    continue;
}
```

Static fields belong to the class rather than an individual object, so the validator ignores them.

**Step 6: Access private fields**

```java
field.setAccessible(true);
Object value = field.get(target);
```

This enables access to private fields when permitted by Java's access-control and module rules.

**Step 7: Validate @NotNull**

```java
if (field.isAnnotationPresent(NotNull.class)) {

    if (value == null) {
        violations.add(
            fieldName + ": must not be null"
        );
    }
}
```

If the annotation is present and the field value is null, a violation is added.

**Step 8: Validate @NotBlank**

```java
if (field.isAnnotationPresent(NotBlank.class)) {

    if (value == null ||
        ((String) value).isBlank()) {

        violations.add(
            fieldName + ": must not be blank"
        );
    }
}
```

This rejects null, empty, and whitespace-only strings.

The homework specifies that `@NotBlank` is used on String fields.

**Step 9: Validate @Range**

```java
Range range =
    field.getAnnotation(Range.class);

if (range != null && value != null) {

    long number = ((Number) value).longValue();

    if (number < range.min() ||
        number > range.max()) {

        violations.add(
            fieldName +
            ": must be between " +
            range.min() +
            " and " +
            range.max()
        );
    }
}
```

`@Range` supports `int`, `long`, `Integer`, and `Long`.

Primitive values are boxed when accessed through reflection, allowing them to be handled as `Number`.

Null wrapper values are ignored by `@Range`.

**Step 10: Sort violations**

```java
Collections.sort(violations);
```

This sorts the violation messages alphabetically using natural String order.
