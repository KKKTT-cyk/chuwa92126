## Question 1.

`Proxy.newProxyInstance(loader, interfaces, handler)` generates, at the first call, the bytecode of a **new class and loads it** with the given class loader. The generated class (named like `$Proxy0`) **extends `java.lang.reflect.Proxy` and implements all the listed interfaces**; the same interface list and loader give the same cached class. Every interface method in it just calls `handler.invoke(...)`, and `equals`, `hashCode` and `toString` are routed to the handler too.

On every call the `InvocationHandler` (single method `Object invoke(Object proxy, Method method, Object[] args) throws Throwable`) receives **the proxy object, the `Method` being called, and the arguments**. It can run code before and after, and forward to the real object with `method.invoke(target, args)`.

Only interfaces can be proxied because the generated class already extends `java.lang.reflect.Proxy` (it holds the handler), and Java has **single inheritance**, so it cannot also extend your class. Passing a class gives `IllegalArgumentException: ... is not an interface`, and casting the proxy to the real class gives `ClassCastException`.

The handler calls the target by reflection, so an exception thrown by the target arrives **wrapped in `InvocationTargetException`**. The handler should unwrap and rethrow the real exception so the caller sees the original one, not the wrapper:

```java
try {
    return m.invoke(target, args);
} catch (InvocationTargetException e) {
    throw e.getCause();   // the caller sees IllegalArgumentException
}
```

## Question 2.

A class is loaded lazily, the first time it is needed, and goes through three phases:

| Phase | What happens |
|---|---|
| Loading | Find the bytes (file, jar, network) and create the `Class` object |
| Linking | **Verification** (the bytecode is valid and safe), **preparation** (static fields get default values such as 0 or `null`), **resolution** (symbolic references become direct ones) |
| Initialization | Static initializers run and statics get their real values, once per class loader and thread-safely |

Initialization is triggered by the first **active use**: `new`, reading or writing a non-constant static field, calling a static method, `Class.forName("X")`, initializing a subclass (the superclass is initialized first), and running `main` of that class. It is **not** triggered by `X.class`, reading a `static final` compile-time constant, creating an array `new X[n]`, `ClassLoader.loadClass`, or `Class.forName(name, false, loader)`.

There are three built-in class loaders (JDK 9+). The **bootstrap** loader (native code, `getClassLoader()` returns `null`) loads `java.base` such as `java.lang.*`. The **platform** loader loads other JDK modules such as `java.sql`. The **application** loader loads your classes from the classpath or module path.

With **parent delegation**, a loader first asks its parent and only tries itself if the parent cannot find the class. Delegation comes first for three reasons: **security** (you cannot replace `java.lang.String` with your own copy, because the bootstrap loader always answers first), **no duplicates** (a class loaded by a parent is reused by all children), and **consistency** (core types must be the same `Class` everywhere, or a `String` passed between two libraries would be incompatible).

## Question 3.

**`serialVersionUID`** is a version number written into the stream. When reading, it must match the class in the reader's JVM, or `InvalidClassException` is thrown. If it is omitted, the JVM computes one from the shape of the class, so any small change breaks old data. It should be declared explicitly (`private static final long serialVersionUID = 1L;`) and increased only for a truly incompatible change.

**`transient`** marks a field that is skipped during serialization. After deserialization it has the default value (for example, a `transient String password` comes back `null`), so it is used for sensitive or non-essential state. It can be restored in `readObject`.

**`readResolve`** lets you substitute the deserialized object. Deserialization creates a new object, which breaks a singleton. Adding `private Object readResolve() { return I; }` replaces the new object with the real singleton, so `de(ser(Single.I)) == Single.I` is `true`.

Deserializing **untrusted data is dangerous** because the byte stream decides which classes are created, and deserialization builds objects and runs special methods (`readObject`, `readResolve`) **without calling constructors**. A crafted stream can chain ordinary library classes (a **gadget chain**) that ends in code execution. Never call `readObject` on data from the network or users. Prefer data-only formats such as JSON or Protocol Buffers, validate state in `readObject`, and if you must read serialized data, restrict it with an `ObjectInputFilter` (allow list and limits such as `maxdepth`, `maxarray`).

## Question 4.

The complete code is in `Coding/hw14/Exprs.java`. All three methods use `switch` with pattern matching and record patterns and have **no `default` branch**, so the compiler checks that every `Expr` subtype is covered.

- **`eval`**: `Num` gives its value; `Var` looks its name up in `env` and throws `IllegalArgumentException("Unbound variable: <name>")` if it is missing; `Add`, `Mul` and `Neg` combine the evaluated children.
- **`show`**: `Num` is shown without a decimal point when it is a whole number (`3.0` is shown as `3`) and with `Double.toString` otherwise; `Var` shows its name; `Add` shows `(<left> + <right>)`; `Mul` shows `(<left> * <right>)`; `Neg` shows `-<operand>`.
- **`simplify`**: the children are simplified first, and then the rules are applied to the result. The cases are written in the order of the rules, so when several rules could apply, the first one wins.

```java
public static Expr simplify(Expr expr) {
    // 1. Simplify the children first
    Expr rebuilt = switch (expr) {
        case Num n -> n;
        case Var v -> v;
        case Add(Expr left, Expr right) -> new Add(simplify(left), simplify(right));
        case Mul(Expr left, Expr right) -> new Mul(simplify(left), simplify(right));
        case Neg(Expr operand) -> new Neg(simplify(operand));
    };
    // 2. Apply the rules to the result; when several rules could apply, the first one wins
    return switch (rebuilt) {
        case Add(Num(double a), Num(double b)) -> new Num(a + b);
        case Mul(Num(double a), Num(double b)) -> new Num(a * b);
        case Add(Num(double a), Expr x) when a == 0 -> x;
        case Add(Expr x, Num(double b)) when b == 0 -> x;
        case Mul(Num(double a), Expr x) when a == 1 -> x;
        case Mul(Expr x, Num(double b)) when b == 1 -> x;
        case Mul(Num(double a), Expr x) when a == 0 -> new Num(0.0);
        case Mul(Expr x, Num(double b)) when b == 0 -> new Num(0.0);
        case Neg(Num(double n)) -> new Num(0.0 - n);
        case Neg(Neg(Expr x)) -> x;
        // any other expression is returned with its simplified children
        case Num n -> n;
        case Var v -> v;
        case Add a -> a;
        case Mul m -> m;
        case Neg n -> n;
    };
}
```
