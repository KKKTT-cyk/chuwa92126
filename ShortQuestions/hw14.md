1. The Proxy.newProxyInstance generates a proxy class at runtime, and an InvocationHandler receives the proxy object,the
method and the arguments on every call, and because Java has single inheritance and the generated class has already extends
java.lang.reflect.Proxy thus it can only implement interfaces. Method.invoke() wraps an exception thrown by the target
method in InvocationTargetException. The handler should rethrow getCause() to preserve the original exception and avoid
exposing the reflection wrapper to the caller.

2. The three phases of class loading:
   Loading: find the bytes and create a class object
   Linking: contains three parts: verification, preparation and resolution, verification means checking the bytecode is valid
   and safe, preparation means allocating static fields, set DEFAULT values(0,null) and resolution means replacing symbolic
   references with direct once.
   Initialization: run static initializers and assign real values to statics.
Situations trigger class initialization: 
   new lazy(); 
   reading or writing a non-constant static field; 
   calling a static method; 
   Class.forName("lazy"); 
   initializing a subclass; 
   running main of that class
The parent delegation model:
three build-in class loaders: 
app loader, platform loader and bootstrap.
Reasons of delegation:
security: We can't replace java.lang.String by putting our own java.lang.String on the classpath; the bootstrap loader
always answer it.
no duplicates: A class loaded by a parent is reused by all children, so shared types(String, list) are the same class everywhere.
consistency: Core types must be identical across all code, or String passes between two libraries would be incompatible.

3. In Java serialization, serialVersionUID is a version number written into the stream in each serializable class. 
Transient is one of the filtering rules that are the decisions every serializer has to make. And readResolve makes us 
substitute the deserialized objects.
Deserializing data from an untrusted source is dangerous because deserialization creates objects and runs special methods
without constructors, a crafted byte stream can build a chain of ordinary library classes that ends in code execution.
These are gadget chains, and they have caused many serious vulnerabilities.
