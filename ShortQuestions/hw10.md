#### Conceptual Questions

**1. 什么是 Kafka？它通常用来解决什么问题？**

Kafka is a distributed event streaming platform that lets applications publish, store, and read streams of events. It is commonly used to connect services, collect logs, build data pipelines, and process data in real time. It helps applications exchange data without needing to communicate directly with each other.

**2. 什么是消息（Message/Record）？一条 Kafka 消息通常可以包含哪些信息？**

A message or record is one piece of data stored in Kafka, such as an order event or a user activity. It can contain a key, a value, a timestamp, and optional headers. Once stored, it also has an offset identifying its position within a specific topic partition.

**3. 什么是生产者（Producer）？它在 Kafka 中承担什么职责？**

A producer is an application that sends messages to Kafka topics. It prepares the records and sends them to the appropriate brokers. It can also influence which partition receives a message through a key, a partitioning strategy, or an explicitly chosen partition.

**4. 什么是消费者（Consumer）？它在 Kafka 中承担什么职责？**

A consumer is an application that reads messages from Kafka topics and processes them. Consumers track their reading positions and can commit offsets so they can resume from a saved position later.

**5. 什么是主题（Topic）？为什么 Kafka 要使用 Topic 对消息进行分类？**

A topic is a named category of messages. Topics help organize different kinds of data so producers know where to send messages and consumers can subscribe to the data they need. Each topic can also have its own settings, such as how long messages are retained.

**6. 什么是 Broker？Kafka 集群中为什么可以有多个 Broker？**

A broker is a Kafka server that stores partition data and handles requests from producers and consumers. Multiple brokers let a cluster distribute storage and processing work across servers. They also allow partition replicas to be placed on different servers, helping the cluster tolerate broker failures.

**7. 什么是分区（Partition）？一个 Topic 为什么可能需要多个 Partition？**

A partition is an ordered log that holds part of a topic's messages. Multiple partitions let Kafka distribute a topic's data across brokers and let multiple consumers in a group process it in parallel. This helps a topic handle more data and higher traffic.

**8. 什么是 Offset？它表示的是消息的全局编号，还是消息在某个 Partition 中的位置？**

An offset is a number assigned to a record that identifies its position within one partition. It is not a global message number across the topic or cluster. Two different partitions can have records with the same offset, so the topic, partition, and offset together identify a record's location.

**9. 什么是消费者组（Consumer Group）？同一个消费者组中的多个消费者如何分工？**

A consumer group is a set of consumers that work together to read topics using the same group ID. In a typical Kafka consumer group, each partition is assigned to only one consumer in that group at a time, although one consumer can handle multiple partitions. Kafka redistributes these assignments when consumers join or leave the group.

**10. 什么是消息键（Key）？Key 会如何影响消息被写入哪个 Partition？**

A key is an optional value used to identify or group related records, such as a customer ID. With the usual key-based partitioning behavior, Kafka's producer hashes the key to choose a partition, so records with the same key normally go to the same partition while the partition count and partitioning strategy stay unchanged. An explicit partition or a custom partitioning strategy can change this behavior.

**11. Topic 和 Partition 有什么区别？请用一句话描述它们之间的关系。**

A topic is a named category of messages, while a partition is one of the ordered logs that make up that topic.

**12. Broker 和 Kafka 集群有什么区别？一个 Broker 是否就等于一个 Kafka 集群？**

A broker is one Kafka server, while a Kafka cluster is the overall system containing one or more brokers working together. A cluster can run with a single broker, but a broker and a cluster refer to different things. Larger clusters use multiple brokers to increase capacity and support replication across servers.

**13. Producer 和 Consumer 是否需要彼此知道对方是谁？请说明原因。**

Producers and consumers do not need to know each other's identities. Producers send records to Kafka topics, and consumers independently read from those topics through Kafka. They still need to agree on the meaning and format of the data, but they do not need a direct connection to each other.

**14. Offset 是由 Producer 决定的吗？消费者为什么需要记录自己的消费位置？**

The producer does not decide a record's offset; Kafka assigns it when the record is appended to a partition's log. Each consumer group maintains its own committed offset for each partition, normally indicating the next record to read when resuming. Saving these positions lets the group resume after a restart or reassignment, independently of other groups.

**15. “Kafka 能保证整个 Topic 中的所有消息严格有序。”这句话是否正确？请说明 Kafka 的顺序保证范围。**

This statement is not correct for a topic with multiple partitions. Kafka maintains record order within each individual partition, but it does not provide one total order across different partitions. A topic with only one partition has a single log order, although the consumer's processing approach still matters if records are processed in parallel.

**16. 如果一个 Topic 有 3 个 Partition，同一个消费者组中有 5 个 Consumer，那么最多有几个 Consumer 能同时消费这个 Topic？其余 Consumer 会怎样？**

At most 3 consumers in that group can actively consume this topic at the same time because each partition is assigned to only one consumer in the group. The other 2 consumers have no partitions from this topic and remain idle for it. They may receive partitions later if the assignments change, or consume other topics if the group subscribes to them.

**17. 两个不同的消费者组订阅同一个 Topic，它们会互相抢消息吗？请解释它们各自能看到哪些消息**

The two groups do not compete for exclusive access to the messages. Each group tracks its own committed offsets for each partition, so one group reading a record does not remove it or advance the other group's position. Both groups can independently read the same retained records, depending on their starting offsets and progress. Records that have already been removed by retention or compaction are no longer available to either group.
