### Question 1.

Apache Kafka is a distributed event streaming platform used to build real-time data pipelines and event-driven applications. It helps decouple services by allowing producers to publish events and consumers to process them independently. Kafka provides high throughput, scalability, fault tolerance, and persistent message storage.

### Question 2.

A Kafka message/record is the basic unit of data stored in Kafka. It contains an optional key, a value, optional headers, and a timestamp. After being written, it is associated with a topic, partition, and offset. The key is commonly used for partition routing, while the value contains the actual business data.

### Question 3.

A Kafka producer is an application that publishes messages to Kafka topics. It is responsible for serializing records, selecting partitions, sending messages to brokers, and handling acknowledgments and retries. Producers do not need to know which consumers will process their messages.

### Question 4.

A Kafka consumer is an application that subscribes to topics and processes messages. Kafka uses a pull model, so consumers retrieve records by calling poll(). Consumers also track and commit offsets to manage their progress and recover after failures.

### Question 5.

A Kafka topic is a logical category used to organize related messages. Producers publish records to topics, and consumers subscribe to them. Topics help separate different types of events and allow independent consumption, scaling, and configuration.

### Question 6.

A Kafka broker is a server that stores topic partitions and handles producer and consumer requests. A Kafka cluster consists of one or more brokers. Multiple brokers enable horizontal scalability, load balancing, replication, and fault tolerance.

### Question 7.

A partition is an ordered, append-only log within a Kafka topic. A topic can have multiple partitions to distribute data across brokers and enable parallel processing. More partitions can improve scalability and throughput, while Kafka guarantees message ordering only within each partition.

### Question 8.

An offset is the position of a record within a specific Kafka partition. It is not a global message ID. Offsets are unique within each partition, and the combination of topic, partition, and offset uniquely identifies a record.

### Question 9.

A consumer group is a set of consumers working together under the same group ID. Kafka distributes topic partitions among consumers in the group. Each partition is assigned to only one consumer within a group at a time, but a consumer can handle multiple partitions. This enables parallel processing and load balancing.

### Question 10.

A message key is an optional field used to determine which partition a record is sent to. Kafka typically hashes the key to select a partition. Messages with the same key are routed to the same partition under a stable partitioning configuration, which helps maintain ordering for related events.

### Question 11.

A topic is a logical category of messages, while a partition is an ordered storage unit within that topic. A topic consists of one or more partitions that enable distributed storage and prarallel processing.

### Question 12.

A broker is an individual Kafka server, while a cluster is a group of brokers working together. A Kafka cluster can contain a single broker, but production clusters usually usually use multiple brokers for scalability, replication, and fault tolerance.
