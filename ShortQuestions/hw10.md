1. Kafka is an open-source distributed event streaming platform. It used primarily to build real-time streaming pipeline.
Kafka helps with decoupling data streams and systems from different sources as a data integration layer, which will allow
a simplified data integration solution.
2. A message/record is the basic data unit that Kafka saves and transports. A message contains Key, value, Timestamp and
Headers. Key could be used to choose partition, value is the real content of the message, and the Headers are metadata, 
like tracking ID.
3. A producer is an application that can write records to topics. It sends records to the partitions based on the record 
key.
4. A consumer is an application that can read records from topics. It pulls records from the signed partitions and tracks
its position using offsets.
5. A topic is a logic grouping of partitions and save related messages. Kafka use topics to organizes the related the 
messages so that producers and consumers can publish and subscribe to specific types of data.
6. A broker is a server that can store partition replicas and serve requests. Multiple brokers distributed data and 
workload across the cluster, which providing scalability and fault tolerance through replications.
7. A partition is an ordered sequence of records within a Kafka topic. Multiple partitions allows data distributed across
the brokers and processed in parallel by consumers, improving scalability and throughput. Ordering is guaranteed within
each partition, not across the topic.
8. Offsets represent the position of a message within a Kafka partition. It is unique within the partition, not the 
globally across the topic.
9. A consumer group is a set of consumers that share the same group ID and work together to consume topics. Partitions 
are distributed among them and each partition assigned to only one consumer within the group at one time. A consumer 
can handle multiple partitions.
10. A key is an optional field in Kafka record. By default, Kafka hashed the key to select a partition, so records with
the same key go to the same partition, provided the partition count stays unchanged.
11. A topic is a logical category of messages, divided into one or multiple partitions that stores the message as ordered
sequences.
12. A broker is a single Kafka server and with a unique broker ID. A Kafka cluster is made with one or multiple brokers
working together. A broker is a member of a cluster, and a single broker could be a cluster.
13. No. Producers and consumers are decoupled through Kafka topics. Producers publish message to topics while consumers
subscribe topics to get messages without needing to know each other's identities.
14. No, offsets are assigned by the broker within every partition. Consumers commit offsets as checkpoints, so they can
resume from the last committed position after a restart.
15. Incorrect. Kafka can guarantee ordering within each partition, but not across partitions in a topic. A topic order
is possible with a single partition.
16. At most three consumers can consume the topic at one time, the rest consumers remain idle, because each partition 
can be only assigned to one consumer within the same group at a time.
17. No, different consumer groups are independently consume and maintain a separate offset. Each group can read all
retained messaged in the topic, depending on its starting offset.
