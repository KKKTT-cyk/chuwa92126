# Homework 12 - Java Advanced Syntax

## 1. Static Nested Class vs. Inner Class

A static nested class does not need an outer object. It can directly access the outer class's static members; accessing instance members requires an object reference.

A non-static inner class is associated with an enclosing object and can access its instance members, even private ones. This is usually implemented with a hidden reference to the outer object. If a long-lived listener or collection retains the inner object, that reference can keep the outer object alive unnecessarily. Modern compilers may omit an unused outer reference, but an inner class that needs the outer instance still retains it.

Prefer a static nested class when it does not need an outer instance. This avoids unnecessary coupling and accidental retention.

## 2. Type Erasure

The compiler checks `List<String>` at compile time, erases its parameterized type to `List`, and inserts casts where needed, such as when reading a String. Generic type variables become their bound, or Object if unbounded. Generic signatures may remain as metadata, but a list object does not enforce its String element type at runtime.

- `new T()` is invalid because the concrete class and an available constructor are not known.
- `new T[10]` is invalid because arrays need a runtime component type, which erased T cannot supply.
- For an Object variable, `obj instanceof List<String>` is invalid because runtime checking cannot verify String elements. Use `obj instanceof List<?>` instead.
- A bridge method is a synthetic compiler-generated method that preserves overriding after erasure. For example, an implementation of `set(T)` as `set(String)` may get a bridge `set(Object)` that casts and delegates to `set(String)`.

## 3. PECS and Variance

PECS means **Producer Extends, Consumer Super**.

| Type | Read | Add |
| --- | --- | --- |
| `List<? extends Number>` | As Number | No non-null value can safely be added; null is type-correct. The actual list could be a List<Double>. |
| `List<? super Integer>` | Safely as Object | Integer values and null. The actual list could be List<Integer>, List<Number>, or List<Object>. |

These are compile-time rules; an unmodifiable list can still reject changes. An extends list is not strictly immutable: operations such as clear or remove may be allowed.

Generics are invariant: `List<Integer>` is not a subtype of `List<Number>`. Otherwise, someone could add a Double through the Number reference and break the Integer list.

Arrays are covariant: `Integer[]` is a subtype of `Number[]`. Arrays retain their component type at runtime, so storing a Double into that Integer array throws ArrayStoreException.

## 4. Annotation Retention and Meta-Annotations

- **SOURCE:** discarded by the compiler.
- **CLASS:** stored in the class file but not available through runtime reflection. This is the default.
- **RUNTIME:** stored and available through runtime reflection.
- `@Target` specifies where the annotation can be used, such as fields or methods.
- `@Inherited` lets a class inherit a class-level annotation from its superclass when queried appropriately. It does not inherit annotations from interfaces or on methods/fields.
- `@Repeatable` allows the same annotation type to appear multiple times on one element, using a declared container annotation.

An annotation needs **RUNTIME** retention to be read through reflection at runtime.

## 5. Class Objects and Reflection

Common ways to obtain a Class object:

```java
Class<?> a = String.class;
Class<?> b = "hello".getClass();
Class<?> c = Class.forName("java.lang.String");
Class<?> d = ClassLoader.getSystemClassLoader().loadClass("java.lang.String");
Class<?> e = int.class; // Also Integer.TYPE
```

Reflection also returns Class objects through methods such as `getSuperclass()` and `Field.getType()`.

`setAccessible(true)` suppresses normal Java access checks for that reflected member, allowing access to private members when permitted. It does not bypass module boundaries: deep reflection into another named module generally requires that package to be opened to the caller. Otherwise, it can throw InaccessibleObjectException.

When the target method itself throws, `Method.invoke()` wraps that throwable in InvocationTargetException. This distinguishes a target failure from reflection errors such as inaccessible methods or wrong arguments. Use `getCause()` to obtain the original throwable.

## 6. Reflection-Based Validator

The validator walks the class hierarchy, reads annotated private instance fields, and checks each annotation independently. It ignores static fields, skips null wrapper values for Range, and sorts all violation messages. A null target throws IllegalArgumentException.

```java
Validator.validate(new Person(" ", 151));
// [age: must be between 0 and 150, name: must not be blank]

Validator.validate(new Person("Tiffany", null));
// [age: must not be null]
```
