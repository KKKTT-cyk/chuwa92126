# java-spring-batch-homework


1. Explain why a simple loop that reads a whole file into memory, parses each line and saves it is not suitable for large batch jobs, and name the Spring Batch feature that addresses each problem.

A simple loop loads the entire file into memory and it can cause OutOfMemoryError. A bad record may stop the whole process, and failure may require restarting from the beginning.

Spring Batch solves these problems with chunk processing to reduce memory usage, skip and retry for error handling, restart support to resume from the last committed chunk, and JobRepository to track status.


2. Explain the difference between `Job`, `Step`, `JobInstance`, `JobExecution` and `StepExecution`, using a daily job that is run with a `runDate` parameter as the example.

Job represents the entire batch process, and Step is one phase of a job. A JobInstance is a logical run identified by the job and its identifying parameters. For example, running dailySettlementJob with runDate=2026-10-08 creates a JobInstance. Each attempt to run that instance is a JobExecution. If the first execution fails and restarted with the same parameters, a new JobExecution is created under the same JobInstance. A StepExecution records each attempt to execute a step.


3. Explain chunk-oriented processing: how reading, processing and writing are organized, where the transaction boundaries are, and how the chunk size affects speed, memory and the amount of work repeated after a failure.

It reads and processes items one at a time, then writes them as a chunk. Each chunk runs in its own transaction and is committed after a successful write. A larger chunk size usually improves performance by reducing commits, but uses more memory and may require more work to be repeated after a failure. A smaller chunk size uses less memory and reduces repeated work, but requires more commits.


4. Compare a tasklet step with a chunk-oriented step, and give a typical use for each one.

A tasklet step performs one task, such as deleting temporary files or archiving a file. It usually finishes by returning FINISHED.

A chunk-oriented step processes large amounts of data using `ItemReader`, `ItemProcessor`, and `ItemWriter`. For example, it can read transactions from a CSV file, process them, and save the results to a database.


5. Describe the contracts of `ItemReader`, `ItemProcessor` and `ItemWriter`: how a reader signals the end of the input, what it means when a processor returns null, and why a writer receives a whole Chunk instead of a single item.

`ItemReader` reads one item at a time and returns `null` at the end of the input. 
`ItemProcessor` transforms, validates, or filters items. If it returns null, the item is filtered out.
`ItemWriter` receives a chunk and it can perform efficient bulk operations, such as batch database inserts.


6. Explain the difference between filtering and skipping an item, and the difference between skip and retry, with an example of an error suited to each.

Filtering happens when processor returns null for a valid but unwanted item, such as a transaction with a zero amount. Skipping happens when an item causes a configured exception, such as an invalid account ID.

Skip is used for permanent errors that should be ignored, and retry is used for temporary errors that may succeed later, such as a database timeout.


7.  Explain why a reader that uses `#{jobParameters['inputFile']}` must be declared `@StepScope`.

Job parameters are available when the job runs, not when the application starts. `@StepScope` creates a new reader for each step execution, allowing it to access the correct inputFile parameter and maintain its reading state.

8.  Describe what happens when a failed job is started again with the same identifying parameters, what the reader and the writer must support for this to work, and when `JobInstanceAlreadyCompleteException` is thrown.

Spring Batch creates a new JobExecution for the same JobInstance and resumes from the last committed chunk. The reader supports saving and restoring its position with ExecutionContext. `JobInstanceAlreadyCompleteExceptio`n is thrown when the same JobInstance has already completed successfully.


9. Compare a multi-threaded step with partitioning, and explain what must be true of the reader, processor and writer in a multi-threaded step.

Multi-threaded step processes chunks using threads within one step. Partitioning divides the data into separate ranges, with each partition handled by its own worker step execution. In a multi-threaded step, the reader, processor, and writer are shared across threads, so they must be thread-safe. Processing order may also change.


10. Describe two pitfalls of starting batch jobs with `@Scheduled` in an application that runs as several instances, and how to address each one.

One is that `@Scheduled` runs on every application instance, which may cause the same batch job to start multiple times. This can be prevented using a distributed lock like ShedLock or one dedicated scheduler.

Another pitfall is that the default scheduler uses a single thread, so a long-running job may delay other scheduled tasks. This can be fixed by increasing the scheduler pool size.
