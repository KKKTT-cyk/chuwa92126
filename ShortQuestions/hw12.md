## Question 1

Explain the difference between a static nested class and an inner (non-static) class. Describe the hidden reference an inner class holds, how it can cause a memory leak, and why a static nested class is usually preferred.

A non-static inner class implicitly holds a reference to its enclosing instance (`Outer.this`) and can directly access its instance members. A static nested class has no such implicit enclosing-instance reference and needs an explicit reference to access instance members. If an inner-class instance survives in a long-lived callback, thread, or collection, it can unintentionally keep its enclosing object reachable and prevent garbage collection. A static nested class is usually preferred when no enclosing instance is needed because it avoids this retention and makes dependencies explicit.

## Question 2

Explain type erasure: what the compiler does with `List<String>`, why `new T()`, `new T[10]` and `obj instanceof List<String>` are not allowed, and what a bridge method is and why the compiler generates it.

Java generics are largely implemented by type erasure. The compiler checks generic types at compile time, then erases most type arguments: `List<String>` becomes raw `List` in bytecode, with casts inserted where needed. `new T()` is invalid because the concrete runtime type of `T` is unavailable. `new T[10]` is invalid because arrays track their component type at runtime, while `T` is erased. `instanceof List<String>` is invalid because the runtime cannot test the erased type argument (use `instanceof List<?>`). A bridge method is a synthetic compiler-generated method that preserves overriding and polymorphism when erasure changes method signatures. For example, a subclass method `String get()` may need a bridge `Object get()` to override an erased generic parent method.

## Question 3

State the PECS rule. For `List<? extends Number>` and `List<? super Integer>`, say which operations (reading, adding) are allowed on each one and why, and explain why generics are invariant while arrays are covariant.

PECS means "Producer Extends, Consumer Super". `List<? extends Number>` produces values safely readable as `Number`, but you cannot add a non-null number because its actual element type could be `Integer`, `Double`, or another subtype. `null` can be added. `List<? super Integer>` accepts `Integer` values (and its subclasses), but reads are only guaranteed to be `Object`, because the actual list might be `List<Integer>`, `List<Number>`, or `List<Object>`. Generics are invariant: `List<Integer>` is not a subtype of `List<Number>`, preventing unsafe insertion. Arrays are covariant: `Integer[]` is a subtype of `Number[]`, but invalid assignments can fail at runtime with `ArrayStoreException`.

## Question 4

Describe the three retention policies (`SOURCE`, `CLASS`, `RUNTIME`) and what `@Target`, `@Inherited` and `@Repeatable` do. Which retention policy must an annotation have to be read through reflection at runtime?

`SOURCE` annotations are discarded by the compiler. `CLASS` annotations are stored in the class file but normally unavailable through runtime reflection; this is the default retention. `RUNTIME` annotations are retained and visible through reflection. `@Target` restricts where an annotation may appear, such as fields or methods. `@Inherited` allows a class-level annotation on a superclass to be inherited by subclasses when queried through the class annotation API; it does not apply to fields, methods, or interfaces. `@Repeatable` permits multiple instances of the same annotation on one declaration, using a container annotation. To read an annotation via runtime reflection, use `@Retention(RetentionPolicy.RUNTIME)`.

## Question 5

List the ways to obtain a `Class` object. Explain what `setAccessible(true)` does and how the module system limits it, and why a method invoked with `Method.invoke` wraps an exception thrown by the target in `InvocationTargetException`.

Common ways to obtain a `Class<?>` object include `String.class` (class literal), `object.getClass()` (existing instance), `Class.forName("java.lang.String")` (by name), and `ClassLoader.loadClass(...)` (through a class loader). Primitive and array class literals such as `int.class` and `String[].class` also work. `setAccessible(true)` requests suppression of Java language access checks so reflection can access private members, but Java's module system can refuse deep reflective access to packages that are not opened to the caller, throwing `InaccessibleObjectException`. `Method.invoke` wraps exceptions thrown by the invoked target method in `InvocationTargetException`, separating failures of the target method from reflection-related errors; call `getCause()` to inspect the original exception.
