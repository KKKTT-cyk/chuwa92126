# Q1.
A static nested class is not tied to any instance of the outer class and can only access its static members. 
An inner class is tied to an outer instance and can access its fields directly. 
To make this possible, the compiler adds a hidden field, this$0, that references the outer object.
This hidden reference can cause a memory leak, if an inner class object lives longer than expected, for example as a listener or a task held by a long-lived scheduler, it keeps the whole outer object reachable, so the garbage collector cannot reclaim it.
A static nested class is usually preferred because it has no hidden reference, uses less memory, and makes dependencies explicit. Use an inner class only when it really needs the outer instance.

# Q2.
Generics exist only at compile time. The compiler checks types, then erases them, List<String> becomes the raw List, 
type parameters are replaced by their bounds (usually Object), and casts are inserted where values are read. 
At runtime, List<String> and List<Integer> are the same class.
Because T is unknown at runtime. new T() would erase to new Object(), and the constructor cannot be checked.
new T[10] fails because arrays need their exact element type at runtime. 
obj instanceof List<String> fails because the runtime object only knows it is a List, not what it contains.
When a subclass overrides a generic method, such as set(Integer) overriding set(T), 
erasure turns the parent method into set(Object), so the signatures no longer match. 
The compiler generates a hidden set(Object) method in the subclass that casts and calls set(Integer), which keeps polymorphism working.

# Q3.
Producer Extends, Consumer Super. 
Use ? extends T when you only read from a collection, and ? super T when you only write to it.
List<? extends Number>: You can read elements as Number, because every element is some kind of Number. 
You cannot add anything except null, because the actual list might be a List<Double> or List<Integer>, and the compiler cannot tell which.

List<? super Integer>: You can add Integer values, because the list holds Integer or one of its supertypes. 
You can only read elements as Object, because the actual list might be a List<Object>.

If List<Integer> were a subtype of List<Number>, you could add a Double to a list of integers, and because of type erasure nothing at runtime would catch it. 
So generics are invariant, and errors are caught at compile time. 
Arrays are covariant because they are reified: the runtime knows the element type and throws ArrayStoreException on a wrong store, so safety is checked at runtime instead.


# Q4.

SOURCE annotations are discarded by the compiler and are only used at compile time, such as @Override. CLASS annotations are stored in the .class file but are not available at runtime; this is the default. 
RUNTIME annotations are kept at runtime and can be read through reflection, such as @Transactional.
@Target restricts where an annotation can be used, such as on methods or classes. 
@Inherited lets a class-level annotation be inherited by subclasses. @Repeatable allows the same annotation to be applied more than once to the same element, using a container annotation.

# Q5.
use a class literal (String.class), call getClass() on an object, call Class.forName("...") with a fully qualified name, or call ClassLoader.loadClass(...). Class.forName initializes the class by default; loadClass does not.
It turns off Java’s access checks for that member, so reflection can read private fields or call private methods. Under the module system, this only works if the target package is opened to the caller, through opens in module-info.java or the --add-opens JVM option. Otherwise it throws InaccessibleObjectException. JDK internals are strongly encapsulated since Java 17.
InvocationTargetException: Method.invoke wraps any exception thrown by the target method so that it can be told apart from errors in the reflective call itself, such as IllegalAccessException. It also lets invoke report any checked exception without declaring them all. The original exception is available through getCause().

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotNull {
}
@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface NotBlank {
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.FIELD)
@interface Range {
    long min();
    long max();
}

class Person {
    @NotBlank
    private String name;
    @NotNull
    @Range(min = 0, max = 150)
    private Integer age;
    Person(String name, Integer age) {
        this.name = name;
        this.age = age;
    }
}

public final class Validator {
    private Validator() {
    }
    public static List<String> validate(Object target) {
        if (target == null) {
            throw new IllegalArgumentException("target must not be null");
        }
        List<String> violations = new ArrayList<>();
        for (Class<?> c = target.getClass(); c != null && c != Object.class; c = c.getSuperclass()) {
            for (Field field : c.getDeclaredFields()) {
                if (Modifier.isStatic(field.getModifiers())) {
                    continue;
                }
                field.setAccessible(true);
                Object value;
                try {
                    value = field.get(target);
                } catch (IllegalAccessException e) {
                    throw new IllegalStateException("Cannot read field " + field.getName(), e);
                }
                checkField(field, value, violations);
            }
        }
        return violations;
    }
    private static void checkField(Field field, Object value, List<String> violations) {
        String name = field.getName();

        if (field.isAnnotationPresent(NotNull.class) && value == null) {
            violations.add(name + ": must not be null");
        }

        if (field.isAnnotationPresent(NotBlank.class)
                && (value == null || (value instanceof String s && s.isBlank()))) {
            violations.add(name + ": must not be blank");
        }

        Range range = field.getAnnotation(Range.class);
        if (range != null && (value instanceof Integer || value instanceof Long)) {
            long v = ((Number) value).longValue();
            if (v < range.min() || v > range.max()) {
                violations.add(name + ": must be between " + range.min() + " and " + range.max());
            }
        }
    }
}
