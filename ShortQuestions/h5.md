1. GraphQL is an API query language that lets clients specify exactly what data they need. Unlike REST, where each endpoint usually returns a predefined response structure, GraphQL gives the client more flexibility in choosing fields and related data. 
2. The main problems GraphQL solves are over-fetching and under-fetching. With REST, an endpoint may return more data than a client needs, or the client may need multiple endpoints to gather related data. GraphQL lets the client request exactly the fields and relationships it needs, which can reduce unnecessary network requests.
3. To use GraphQL, the backend first defines a strongly typed schema describing the available types, queries, and mutations. The client sends a GraphQL query specifying the fields it needs, usually to a single /graphql endpoint. The server then uses resolvers to fetch the requested data from databases, caches, or other services.
4. The main difference from REST is that REST usually has multiple resource-based endpoints with server-defined response structures, while GraphQL typically uses one endpoint and allows the client to control the response shape. GraphQL is especially useful when different clients, such as mobile and web, need different views of highly connected data. However, it also introduces challenges such as caching, query complexity, and the N+1 query problem, so I would choose it only when that flexibility provides real value.
