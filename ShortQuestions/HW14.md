1.Proxy.newProxyInstance() generates—or reuses—a runtime proxy class that extends Proxy and implements the specified interfaces, then creates an instance associated with your InvocationHandler. docs.oracle.com
Each intercepted call invokes handler.invoke(proxy, method, args): the proxy object, a Method identifying the called method, and its arguments. Primitive arguments are boxed; args is null for a method with no parameters. docs.oracle.com
JDK dynamic proxies support interfaces only. Their generated class already extends Proxy, and Java does not allow it to extend a target class as a second superclass.
When the handler delegates using Method.invoke(), target exceptions are wrapped in InvocationTargetException. Rethrowing getCause() preserves the original exception; leaking the wrapper can cause an UndeclaredThrowableException
2.Java handles a class in three phases: loading finds its bytecode and creates a Class object; linking verifies the bytecode, prepares static fields with default values, and resolves symbolic references (possibly later); initialization executes static field initializers and static blocks. docs.oracle.com

Initialization happens on first active use: creating an instance, calling a declared static method, reading or assigning a declared static field (except reading a compile-time constant), or certain reflective operations. A superclass initializes before its subclass. docs.oracle.com

The three built-in loaders are bootstrap → platform → application (system). By default, a loader checks whether the class is already loaded, asks its parent, and searches itself only if the parent cannot find it. Parent-first delegation lets applications share the same platform classes and prevents an application class from replacing a core class such as java.lang.String.
