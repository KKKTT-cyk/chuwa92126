## Question1:What is ORM?
ORM (Object-Relational Mapping) is a programming technique that maps objects in an object-oriented programming language, such as Java, to tables in a relational database, such as MySQL, PostgreSQL, or Oracle.
The purpose of ORM is to allow developers to interact with database records through Java objects instead of manually writing SQL statements for every database operation.

The mapping works as follows:
Java concept	Database concept	Example
Java class	Database table	Student → students
Java object	Database row	A Student instance → one student record
Java field	Database column	name → name column

## Question2:What Is the Difference Between JPA and Hibernate?
JPA is a Java specification that defines standard interfaces, annotations, and rules for managing relational data through Java objects.
Hibernate is an ORM framework that implements the JPA specification.

Why Is JPA a Standard and Hibernate an Implementation?
JPA defines what operations a persistence framework should support, while Hibernate determines how those operations are implemented.
This separation allows applications written against JPA APIs to switch between compliant JPA providers, such as Hibernate and EclipseLink, although provider-specific behavior and configurations may require changes.

## Question3:What Problem Does Spring Data JPA Solve?
1.Spring Data JPA simplifies the development of the database access layer by reducing boilerplate repository code.
Without Spring Data JPA, developers often need to manually implement common persistence operations using EntityManager, including saving, finding, updating, and deleting entities.

2.Why Does This Work Without Writing an Implementation?
JpaRepository is a Spring Data JPA interface that defines common persistence operations.
At application startup, Spring Data JPA creates repository proxy implementations automatically. These proxies delegate common operations to Spring Data JPA infrastructure, typically using an implementation such as SimpleJpaRepository.
That implementation uses JPA's EntityManager to perform persistence operations.
For instance, save() uses JPA persistence operations such as persist() or merge(), depending on whether the entity is considered new.

3.What Is the Relationship Between Spring Data JPA, JPA, and Hibernate?
JPA, or Jakarta Persistence API, is a specification. It defines a standard way to map Java objects to relational database tables and perform persistence operations.
Hibernate is an ORM framework that implements the JPA specification. It handles the actual persistence operations, including generating SQL queries, mapping database records to Java objects, managing entity states, dirty checking, caching, and lazy loading.
Spring Data JPA is an abstraction built on top of JPA. Its main purpose is to reduce boilerplate code in the data access layer.

In summary, JPA defines the standard, Hibernate implements the standard, and Spring Data JPA simplifies how developers interact with JPA.

## Question4:What Is an Entity?
An Entity is a Java class that represents persistent data stored in a relational database.
Each entity instance typically represents one row in a database table.

1. @Entity
Marks the Java class as a JPA entity.
This tells the JPA provider that objects of this class can be managed by the persistence context and mapped to database records.
2. @Table(name = "students")
Specifies the database table associated with the entity.
3. @Id
Identifies the entity's primary key field.
4. @GeneratedValue
Specifies that the primary key value should be generated automatically.

## Question5:Why Does an Entity Need a Primary Key?
A primary key uniquely identifies each record in a relational database table.
In JPA, every entity must have a primary key, identified using the @Id annotation or an equivalent composite-key mapping.

Why Might a New Entity Have No ID Before Saving?
Consider the following example:

Student student = new Student();
student.setName("John");
System.out.println(student.getId());
// null
studentRepository.save(student);
System.out.println(student.getId());
// Generated ID, for example: 1001

When the object is first created, it exists only in Java memory.
Because its ID uses @GeneratedValue, the identifier has not necessarily been generated yet.
When the entity is persisted, Hibernate coordinates ID generation according to the chosen generation strategy.
With IDENTITY, the database typically generates the ID during insertion. With SEQUENCE, Hibernate can obtain an ID before executing the INSERT.
Therefore, the exact time at which the ID becomes available depends on the generation strategy and persistence lifecycle.

## Question7:What Is the Owning Side?
In JPA, the owning side of a bidirectional relationship is the side that controls how the relationship is mapped and synchronized in the database.
1. Which Side Is the Owning Side?
   The Enrollment entity is the owning side.
Specifically, the student field in Enrollment owns the relationship with Student.
This is because the Enrollment entity contains the @ManyToOne association with the @JoinColumn annotation.
2. Which Database Column Is the Foreign Key?
   student_id
   It is stored in the enrollments table and references the primary key in the students table.
3. What Is the Owning Side Responsible For?
   The owning side determines which entity is associated with another entity.

## Question8:What Does mappedBy = "student" Mean?
The mappedBy attribute indicates that this relationship is the inverse (non-owning) side of a bidirectional JPA association.
It tells Hibernate that the relationship is already managed by a field in another entity.
mappedBy tells Hibernate:
"The relationship is managed by the field named student in the Enrollment entity."

Why Is It "student" Instead of "student_id"?
Because mappedBy references the Java field name in the associated entity, not the database column name.

In this example:
Name	Meaning
student	Java field in the Enrollment entity
student_id	Foreign key column in the enrollments table
mappedBy = "student"	References the Java field that owns the relationship
@JoinColumn(name = "student_id")	Specifies the database foreign key column

JPA operates on entity metadata and Java property mappings, so mappedBy must refer to the association field in the owning entity.

Using:
@OneToMany(mappedBy = "student_id")

would be incorrect because student_id is not the name of the relationship field in Enrollment.

## Question9:What Is the Difference Between LAZY and EAGER Loading?
LAZY and EAGER are two fetching strategies in JPA that determine when related entities are loaded from the database.
LAZY Loading
LAZY loading means that related data is not necessarily loaded when the parent entity is first retrieved.
Instead, Hibernate can load the related data when the application accesses that relationship.

EAGER Loading
EAGER loading means that related data must be loaded as part of retrieving the entity, rather than being deferred until the relationship is accessed.

Why Should We Avoid Making Every Relationship EAGER?
This creates unnecessary database queries, memory consumption, and response latency.
EAGER loading can also contribute to the N+1 query problem, where the application executes one query to load parent entities and additional queries to load their relationships.

## Question10:How Does an HTTP Request Reach the Database?
Suppose a client wants to find all Enrollment records for the Student whose ID is 1.

The client sends: GET /students/1/enrollments

Step 1: Controller Layer
The Controller receives the HTTP request, extracts the studentId, and delegates the operation to the Service layer.
The Controller is responsible for HTTP-related operations, such as request routing, parameter extraction, validation, and returning responses.

Step 2: Service Layer
The Service layer implements business logic and coordinates repository operations.
The Service layer retrieves the Enrollment entities and converts them into DTOs for the HTTP response.

Step 3: Repository Layer
The Repository layer provides an abstraction for database access.
Spring Data JPA automatically generates the implementation of this repository method based on the method name.

Step 4: Hibernate Layer
Spring Data JPA uses the JPA EntityManager, and Hibernate acts as the underlying JPA provider.
Hibernate translates the requested entity operation into SQL appropriate for the configured database.

Step 5: JDBC Layer
JDBC (Java Database Connectivity) provides the standard Java API for communicating with relational databases.
Hibernate uses JDBC to execute SQL commands through the configured JDBC driver.

Step 6: Database Layer
The relational database receives the SQL statement, executes it, and returns the matching rows.

The database sends these records back through JDBC to Hibernate.
Hibernate maps them into Enrollment entities, which are returned through the Repository to the Service.
The Service converts them into DTOs, and the Controller returns the response to the client as JSON.

Summary of Each Layer's Responsibility
Layer	Responsibility
HTTP Request	Sends a request to retrieve enrollment information
Controller	Handles HTTP routing, parameters, and responses
Service	Executes business logic and manages transaction boundaries
Repository	Provides convenient database access methods
Hibernate	Translates ORM operations into SQL and maps results to entities
JDBC	Communicates with the database through SQL execution
Database	Stores data, executes SQL queries, and returns results
