### Question 1.

ORM stands for Object-Relational Mapping. It maps Java classes to database tables, Java objects to rows, and object fields to columns. It allows developers to work with Java objects instead of manually writing SQL and converting query results. In Spring Boot, Hiberate is a common ORM implementation.

### Question 2.

JPA is a standard specification that defines APIs and annotations for object-relational persistence in Java. Hibernate is an ORM framework that implements the JPA specification. JPA defines how persistence should work, while Hibernate performs actual operations such as generating SQL, managing entity states, and loading data from the database.

### Question 3.

Spring Data JPA simplifies database access by automatically generating repository implementations and providing built-in CRUD methods. By extending `JpaRepository<Student, Long>`, we can use methods such as `save()`, `findById()`, and `deleteById()` without implementing them ourselves. Spring Data JPA uses JPA, which is typically implemented by Hibernate, to perform database operations.

### Question 4.

An entity is a Java class managed by JPA that typically represents a database table. `@Entity` marks the class as persistent, `@Table` specifies the table name, `@Id` identifies the primary key, and `@GeneratedValue` configures automatic primary key generation. Each persisted entity instance generally corresponds to a row in the database.

### Question 5.

An entity needs a primary key to uniquely identify each database record and allow JPA to manage, update, and delete the correct entity. The `@Id` annotation marks the primary key field. A newly created entity may have a null ID because the database has not generated it yet. We commonly use `Long` instead of `long` so that null can represent an unassigned ID.

### Question 6.

Student and Course have a many-to-many relationship, but the relationship itself contains additional business data, such as enrollment time, status, and grade. Therefore we model it using an Enrollment association entity instead of a simple `@ManyToMany`. Enrollment contains two `@ManyToOne` relationships and allows us to store additional attributes and enforce a unique student-course combination.

### Question 7.

The owning side is the side of a JPA relationship responsible for managing its database relationship mapping. In this example, `Enrollment.student` is the owning side because the `enrollment` table contains the `student_id` foreign key. Hibernate uses the owning side to determine the foreign key value when persisting the relationsip.

### Question 8.

`mappedBy = "student"` indecates that `Student.enrollment` is the inverse side of the relationship, while `Enrollment.student` is the owning side. The value `"student"` refers to the Java field name in the Enrollment entity, not the database column `student_id`. It tells Hibernate that both sides represent the same relationship and prevents unnecessary additional relationship mapping.

### Question 9.

LAZY loading fetches related entities only when they are accessed, while EAGER loading requires related entities to be initialized when the parent entity is loaded. LAZY can reduce unnecessary database access and memory usage. We should avoid making every relationship EAGER because it can cause excessive queries, expensive joins, and poor performance. For relationships that are definitely needed, we can use explicit fetch joins or entity graphs.

### Question 10.

An HTTP request first reaches the Controller, which handles request parameters and delegates to the Service. The Service applies business logic and calls the Repository. Spring Data JPA provides the repository implementation, and Hibernate translates persistence operations into SQL. JDBC executes the SQL against the database. The results are then mapped into Java entities, processed by the Service, and returned through the Controller as an HTTP response.
