1.ORM (Object-Relational Mapping) connects Java objects to relational database tables:
- Java class ↔ database table
- Java object ↔ database row
- Java field ↔ database column
  It lets you work with objects instead of writing SQL for every operation.
2.JPA is a standard that defines how Java applications map objects to databases. Hibernate is a library that implements that standard.

You can think of JPA as the rules and Hibernate as one tool that follows them.
3. Spring Data JPA reduces the amount of repository code you have to write. It creates an implementation of the interface at runtime and provides methods such as save() and findById().

Spring Data JPA uses JPA, and Hibernate is commonly used to implement JPA.
4.  An Entity is a Java class that JPA maps to a database table.
- @Entity marks the class as an entity.
- @Table(name = "students") specifies its database table.
- @Id marks the primary key field.
- @GeneratedValue tells JPA to generate the ID value.
5. A primary key gives each database row a unique identity, so it can be found and updated reliably. @Id marks the field that serves as that key.

A new Entity may not have an ID yet because the database or JPA provider may assign it when the Entity is saved.
6. Students and courses have a many-to-many relationship: one student can take many courses, and each course can have many students.

An Enrollment Entity represents each student’s registration in a course. It also gives you a place for details about that registration, such as the enrollment date or grade.
7.The owning side is the side of a relationship that defines and manages the foreign key.

For a typical Student–`Enrollment` relationship:
1. Enrollment is the owning side because it has the student relationship field.
2. The student_id column in the enrollments table is the foreign key.
3. The owning side tells JPA which related record to store in that foreign key.

8.On Student, mappedBy = "student" means the relationship is managed by the student field on Enrollment.

"student" is the Java field name in Enrollment. JPA uses that field to find the relationship mapping; student_id is the database column name.
9. - LAZY loads related data only when you access it.
- EAGER loads related data immediately along with the Entity.
  Relationships are often better loaded lazily because eager loading can fetch more data than needed, slow down queries, and create unexpectedly large results.
10.For a request to find a student’s enrollments by studentId:
1. Controller: Receives the request and its studentId.
2. Service: Applies the application’s logic and calls the repository.
3. Repository: Runs the requested database operation.
4. JPA / Hibernate: Maps the operation to SQL; Hibernate is a common JPA implementation.
5. JDBC: Sends the SQL to the database.
6. Database: Finds the matching rows and returns the results.
