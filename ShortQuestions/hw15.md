# Data Access Homework

1. 什么是 ORM？

ORM stands for Object-Relational Mapping. It maps Java classes to database tables, objects to rows, and fields to columns. It allows us to work with Java objects when reading and writing database data. For example, the Student class maps to the students table. Each Student object represents one student row, and its name field maps to the name column. An ORM framework converts query results into objects and translates persistence operations into SQL.


2. JPA 和 Hibernate 有什么区别？

JPA is a specification for Java persistence. It defines standard annotations and APIs, such as `@Entity`, `@Id`, and `EntityManager`, for mapping and managing persistent objects.

Hibernate is an implementation of JPA. It reads entity mappings, generates SQL, maps query results to objects, and manages entity states.

JPA defines the rules and expected behavior, while Hibernate provides the implementation that performs the work.


3. Spring Data JPA 解决了什么问题？

Spring Data JPA reduces repetitive data access code by providing a repository abstraction. Developers can declare a repository interface instead of manually implementing common CRUD operations. 

```java
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```
Student is the entity type, and Long is its primary key type. By extending JpaRepository, the interface inherits methods such as `save()`, `findById()`, `findAll()`, and `deleteById()`. Spring Data JPA creates a repository proxy at runtime and supplies the behavior for these methods.

Spring Data JPA builds on JPA. Hibernate commonly serves as the JPA implementation, handling persistence operations and SQL generation.


4. 什么是 Entity？

Entity is a Java object managed by JPA that has a persistent identity and represents a row in database table.
The purposes of the annotations:
   - `@Entity` declares the class as a JPA entity.

   - `@Table(name = "students")` specifies that the entity maps to the students table

   - `@Id` marks the field as the entity’s primary key

   - `@GeneratedValue` specifies the primary key is generated according to a generation strategy


5. 为什么 Entity 需要 primary key？

An entity needs a primary key so that JPA and the database can uniquely identify it. Other fields, such as a student's name, may contain duplicate values. Primary key lets the application retrieve, update, or delete a specific record reliably.

`@Id` identifies the field or property that represents the primary key.

A newly created entity may not have an ID because its ID is generated during persistence. For example, with `GenerationType.IDENTITY`, the database generates the ID when the row is inserted. Before that, a `Long` ID field can be `null`, indicating that no ID has been assigned.


6. 为什么 Student 和 Course 之间需要 Enrollment？

A `@ManyToMany` mapping can represent the links between students and courses. However, an enrollment may have its own attributes, such as enrollment time, status, or grade. These attributes belong to a particular student-course relationship. Having `Enrollment` entity allows us to store and manage this relationship data. It turns the relationship into two many-to-one associations: each enrollment belongs to one student and one course.
For example, `enrolledAt` belongs in `Enrollment` because it records when a particular student enrolled in a particular course. It does not describe the student or course independently.


7. 什么是 owning side？
   
```java
public class Enrollment {
    @ManyToOne
    @JoinColumn(name = "student_id")
    private Student student;
}
```

   - Owning side: `Enrollment.student` is the owning side of the relationship.
   - Foreign key: The `student_id` column in the `enrollments` table is the foreign key referencing the primary key of the `students` table.
   - The owning side controls the persisted relationship by determining the foreign key value. When an enrollment references a particular student, Hibernate uses that student's ID as the value of `student_id`.


8. `mappedBy = "student"` 表示什么？

```java
@OneToMany(mappedBy = "student")
private List<Enrollment> enrollments;
```
`@OneToMany` means that one student can have multiple enrollments. `mappedBy = "student"` declares this collection as the inverse side of the relationship and identifies `Enrollment.student` as the owning side. `"student"` refers to the Java field named student in the `Enrollment` entity, not the database column `student_id`. The database column is specified by `@JoinColumn(name = "student_id")` on `Enrollment.student`. This tells JPA that both sides represent the same relationship and use the existing foreign key mapping.


9.  LAZY 和 EAGER 有什么区别？

LAZY generally delays loading related data until the application accesses it. For example, a student's enrollments may remain unloaded until the application reads the enrollment collection.

EAGER requires the specified related data to be fetched when the entity is loaded, even if the application does not use it. This may happen through joins or additional queries.

Relationships should not all be EAGER because this can load unnecessary data, increase database queries and memory usage, and slow down requests. Fetching should match the data needed for each operation.
