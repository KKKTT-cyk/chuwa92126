# Q1.
A log record contains the event, what happened and when.
A metrics record contains numeric values at regular points in time.
A traces record contains the whole request trace including the time spent in each span.
Logs give the detail, metrics give the big picture and traces show where the time goes.

Log storage volume grows with the number of requests or the traffic, because each request generates log events, more requests more logs.
Metrics storage volume grows with number of label combinations, more combinations means more data to store and calculate.
Traces storage volume grows with number of requests multiplied by also the number of spans.

Logs are best at explaining what happened and when
Metrics are best at showing the trends and detecting what wrong.
Traces  are best at locating where the time spent of each call and where errors occur across a request’s call chain.

Most of the time services are healthy,but logs,metrics and traces are still being generated constantly.
That means writes are heavy.We usually query when there are some problems, so the telemetry pipeline is high-throughput write-heavy, low-frequency-read system.


# Q2.
Full-text inverted index uses Elasticsearch or others build on lucene, and every token is indexed.
Label-index plus compressed chunks in object storage only index a small set of labels, and log text is stored in compressed chunks and scanned at query time.

Write cost of Full-text is high because it needs to do tokenize, update index, and merge segment, and the storage cost is also high, because of large index and usually need store data on fast disks.
This is why query arbitrary text or query narrowed by label is fast, but these mechanisms both increase the complexity of the operations. overall it is suit for moderate volume with heavy search needs.

Label-index has lower write and storage cost, because of the data is appended and compressed. So the query by arbitrary text is slow, but query by label and time range is fast, because it can filter data fast.
it's suit for high volume with predictable access paths. for example this service last minutes. because if the query pattern is fixed the query is fast and the storage is cheap.

# Q3.
Push: Producer sends data to collector, the producers know the collector address, it's hard to detect a dead target because absence of data is ambiguous.  Producers can overwhelm the collector.
Pull: collectors requests data from each target, but they need to know and maintain target address, it's easy to know if a target down or not, and the collector controls the rate and time of collection.
