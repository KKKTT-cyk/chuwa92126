1. ORM stands for Object-Relational Mapping, which is responsible for transformation between java object and relational
database table. For example, we have a java Student class:
public class Student{
    private String name;
    private String gender;
    private int age;
    public Student(String name, String gender, int age) {
        this.name = name;
        this.gender = gender;
        this.age = age;
   }
}
And initialize a java object: Student s1 = new Student("Jenny", "female", 18);
Then the correspondent table and row in database are as below:
The students table:
   | name | gender | age |
   |  --- |  ---   | --- |
   | Jenny| female | 18  |
Thus the three pairs relationships are:
   | Java | Database | Example |
   |------|----------|---------|
   | class | table | `Student` class ↔ `students` table |
   | object | row | `s1` object ↔ `Jenny, female, 18` this row |
   | field | column | `name` field ↔ `name` this column, same for the other columns |
2. JPA stands for Jakarta Persistence API, it is a standard for Java persistence which defines annotation for Entity 
mapping(@Entity and @Id), interfaces of operation entities(EntityManager) and their behaviours. Usually JPA need an 
implementation instead of providing the specific implementations for these operations.
Hibernate is the most common JPA implementation. It provides the specific implementation according to JPA, for example:
read entity annotation, generate SQL and transform the query result to object. Thus, JPA is the standard while Hibernate
is the implementation. For example, entityManager.persist(student), JPA specifies how the persist() method is used and
defines its semantics. While Hibernate implements this operation at runtime and executes the corresponding INSERT SQL
statement at appropriate time.
3. Spring Data JPA is the repository abstraction based on the JPA, which could reduce the repeated database access and
eliminate the need to manually implement common CRUD operations for each entity. In this example, the interface 
StudentRepository extends JpaRepository, which also inherits save() and findById() method declarations. When Spring starts
and scans this interface, it will create corresponding Repository proxy and registers as a bean. And when we call the 
common CRUD operations, the proxy will delegate them to SimpleJpaRepository, which uses JPA's EntityManager to perform 
the operations. The relationship among Spring data JPA, JPA and Hibernate is: Spring data JPA provides Repository proxy 
and common implements of CRUD operations, JPA defines persistent interfaces and behaviors standard and Hibernate will
implement JPA which could read entity annotation and generate SQL statement ect.
4. Entity is a java object that managed by JPA and usually can be saved to tables in database.
@Entity declare JPA entity, which means this class is managed by JPA;
@Table(name = "students") specified the table that is students;
@Id declares primary key to uniquely identifies a row; 
@GeneratedValue is the strategy of ID generation which means who could generate ID.
5. Because @ID declares the primary key and the primary key uniquely identifies a row in a table. And If the ID is 
generated by the database, such as with GenerationType. IDENTITY, a new entity may have a null ID because it has not 
been inserted yet. After insertion, Hibernate retrieves the generated ID and assigns it to the entity.
6. The relationship between student and class is many to many, but the enrollment also has other enrollment time and state,
thus we need an enrollment entity to save these data, instead of just using @ManyToMany. For example, enrollmentTime 
belongs in Enrollment because it records when a specific student enrolled in a specific course.
7. In this relationship, Enrollment is the owning side, student_id is the foreign key, and it referenced to the primary 
key for student table. Owning side is responsible for maintaining this relationship and controlling the foreign key inserts
and updates in the databases.
8. This configuration means that:
Student.enrollments is not a separate relationship, it represents the same relationship as Enrollment.student, 
Enrollment.student is the owning side and use the existing foreign key enrollment.student_id instead of creating another
join table or mapping. And in the configuration, mappedBy refers to the Java field that owns the relationship in the 
other entity. Therefore, it uses student. The database foreign key column, student_id, is specified by @JoinColumn.
9. LAZY means loading when we really need to access that relationship, EAGER means loading the relationship when loading
the entity regardless of need it or not. The relationship should not be set as EAGER because we need to avoid loading
data that we don't need. Loading them eagerly increases database access and memory usage. Prefer loading on demand and 
explicitly fetching related data when needed.
