
# Data Access Homework — Answers

## 1. 什么是 ORM？

ORM（Object-Relational Mapping，对象关系映射）是一种将 Java 对象与关系型数据库中的数据进行映射的技术。

ORM 的主要作用是让开发者通过操作 Java 对象来访问数据库，而不需要为每个操作手动编写 SQL。

对应关系：

| Java | Database |
|---|---|
| Java class | Database table |
| Java object | Database row |
| Java field | Database column |

例如：

```java
@Entity
@Table(name = "students")
public class Student {
    @Id
    private Long id;

    private String name;
    private Integer age;
}
```

对应数据库：

```sql
CREATE TABLE students (
    id BIGINT PRIMARY KEY,
    name VARCHAR(255),
    age INTEGER
);
```

**总结：** ORM 将 Java 对象与数据库表关联起来，简化数据库操作。

## 2. JPA 和 Hibernate 有什么区别？

JPA（Java Persistence API）是 Java 中用于对象关系映射和数据持久化的一套标准规范。

JPA 定义了 Entity 如何映射数据库、如何进行 CRUD 操作，以及如何管理 Entity 的生命周期。

例如：

- `@Entity`
- `@Table`
- `@Id`
- `@OneToMany`
- `@ManyToOne`

Hibernate 是一个 ORM 框架，也是 JPA 的常见实现之一。

Hibernate 负责：

1. 将 Java Entity 映射到数据库。
2. 生成并执行 SQL。
3. 管理 Entity 的生命周期。
4. 处理 Entity 之间的关联关系。
5. 提供缓存和延迟加载等功能。

例如：

```java
entityManager.persist(student);
```

`EntityManager` 是 JPA 定义的接口，而 Hibernate 可以提供底层实现。

**总结：** JPA 是标准（Specification），Hibernate 是实现（Implementation）。JPA 定义规则，Hibernate 负责具体执行。

## 3. Spring Data JPA 解决了什么问题？

Spring Data JPA 是 Spring 提供的数据访问框架，主要目的是减少重复的数据库访问代码。

如果只使用 JPA，开发者通常需要自己编写持久化操作：

```java
entityManager.persist(student);

Student student =
    entityManager.find(Student.class, 1L);
```

使用 Spring Data JPA，只需要定义一个 Repository 接口：

```java
public interface StudentRepository
        extends JpaRepository<Student, Long> {
}
```

就可以直接使用：

```java
studentRepository.save(student);
studentRepository.findById(1L);
studentRepository.findAll();
studentRepository.deleteById(1L);
```

这是因为 `JpaRepository` 已经定义了常用的 CRUD 方法。

Spring Data JPA 会在运行时为 Repository 接口创建代理对象，并通过默认实现完成数据库操作，因此开发者不需要手动编写实现类。

三者之间的关系：

```text
Spring Data JPA
      |
      v
     JPA
      |
      v
   Hibernate
      |
      v
     JDBC
      |
      v
   Database
```

- Spring Data JPA：简化 Repository 开发。
- JPA：定义数据持久化标准。
- Hibernate：实现 JPA，负责 ORM 和 SQL 执行。

**总结：** Spring Data JPA 简化数据库访问，JPA 定义标准，Hibernate 实现具体的数据库操作。

## 4. 什么是 Entity？

Entity（实体）是一个能够被 JPA 管理并映射到数据库表的 Java 类。

通常一个 Entity 对象对应数据库表中的一条记录。

例如：

```java
@Entity
@Table(name = "students")
public class Student {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String name;
}
```

### @Entity

表示当前 Java 类是一个 JPA Entity，可以由 JPA 进行持久化管理。

### @Table(name = "students")

指定 Entity 对应的数据库表名为 `students`。

### @Id

指定 Entity 的主键字段，用于唯一标识每个 Entity。

### @GeneratedValue

指定主键值的生成方式。

例如：

```java
@GeneratedValue(strategy = GenerationType.IDENTITY)
```

表示使用数据库的 identity 或自增机制生成主键。

**总结：** Entity 是 Java 对象与数据库表之间的映射载体，JPA 注解用于定义映射规则。

## 5. 为什么 Entity 需要 Primary Key？

Primary Key（主键）用于唯一标识数据库表中的每条记录。

在 JPA 中，`@Id` 用于指定 Entity 的主键。

例如：

```java
@Id
@GeneratedValue(strategy = GenerationType.IDENTITY)
private Long id;
```

Entity 需要主键的原因：

1. 唯一标识每个 Entity。
2. 帮助 Hibernate 区分不同对象。
3. 支持更新和删除操作。
4. 帮助 JPA 管理 Entity 的生命周期和状态。

例如：

| id | name |
|---|---|
| 1 | Alice |
| 2 | Bob |
| 3 | Alice |

虽然两个学生都叫 Alice，但是 ID 不同，因此是两个不同的 Entity。

### 为什么新创建的 Entity 可能没有 ID？

因为 ID 可能由数据库自动生成。

例如：

```java
Student student = new Student();
student.setName("Alice");

System.out.println(student.getId());
// null

studentRepository.save(student);
```

如果使用 `GenerationType.IDENTITY`，通常需要执行 INSERT 后数据库才会生成 ID。

不同的 ID 生成策略可能有不同的生成时机。例如使用 sequence 时，Hibernate 可能在 INSERT 之前就获取 ID。

**总结：** Entity 需要主键来唯一标识和管理对象。对于自动生成的主键，在相应的持久化操作发生之前，ID 可能为 null。

## 6. 为什么 Student 和 Course 之间需要 Enrollment？

Student 和 Course 之间是多对多（Many-to-Many）关系。

一个 Student 可以选择多门 Course，一门 Course 也可以被多个 Student 选择。

虽然可以直接使用 `@ManyToMany`，但是实际业务中的选课关系通常包含额外的信息。

例如：

- `enrollmentDate`：选课日期。
- `grade`：课程成绩。
- `status`：选课状态。

这些字段属于学生与课程之间的选课记录，而不是单独属于 Student 或 Course。

因此，创建独立的 Enrollment Entity 更合理。

关系结构：

```text
Student
   |
   | One-to-Many
   v
Enrollment
   ^
   | One-to-Many
   |
Course
```

也可以表示为：

```text
Student 1 ---- N Enrollment N ---- 1 Course
```

示例代码：

```java
@Entity
public class Enrollment {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @ManyToOne
    @JoinColumn(name = "student_id")
    private Student student;

    @ManyToOne
    @JoinColumn(name = "course_id")
    private Course course;

    private String grade;

    private LocalDate enrollmentDate;
}
```

通过 Enrollment，可以把原来的多对多关系拆分为两个一对多关系。

**总结：** Enrollment 不仅表示 Student 和 Course 的关联，还可以保存选课日期、成绩等业务信息，使数据库结构更清晰、更容易扩展。

## 7. 什么是 Owning Side？

Owning side（拥有方）是 JPA 双向关联关系中负责维护数据库关联关系的一方。

题目代码：

```java
public class Enrollment {

    @ManyToOne
    @JoinColumn(name = "student_id")
    private Student student;
}
```

### 1. 哪一边是 owning side？

`Enrollment` 是 owning side。

因为 Enrollment 中使用了 `@ManyToOne` 和 `@JoinColumn`，定义了与 Student 的关联以及外键列。

### 2. 哪个 database column 是 foreign key？

`enrollments` 表中的 `student_id` 是 foreign key。

它引用 `students` 表中的主键。

例如：

```sql
CREATE TABLE enrollments (
    id BIGINT PRIMARY KEY,
    student_id BIGINT,
    FOREIGN KEY (student_id)
        REFERENCES students(id)
);
```

### 3. Owning side 负责什么？

Owning side 负责定义和维护数据库中的关联关系。

例如：

```java
enrollment.setStudent(student);
```

当这个变更被持久化时，Hibernate 会根据 owning side 的状态更新对应的外键值。

如果只修改双向关联中非 owning side 的集合，而没有同步 owning side，通常不会更新对应的外键关系。

**总结：** Enrollment 是 owning side，`student_id` 是外键，owning side 负责数据库关联关系的持久化更新。

## 8. mappedBy = "student" 表示什么？

题目代码：

```java
@OneToMany(mappedBy = "student")
private List<Enrollment> enrollments;
```

通常定义在 Student Entity 中。

`mappedBy = "student"` 表示当前关系由 Enrollment Entity 中名为 `student` 的 Java 字段维护。

例如：

```java
@Entity
public class Student {

    @Id
    private Long id;

    @OneToMany(mappedBy = "student")
    private List<Enrollment> enrollments;
}
```

Enrollment：

```java
@Entity
public class Enrollment {

    @Id
    private Long id;

    @ManyToOne
    @JoinColumn(name = "student_id")
    private Student student;
}
```

这里有两个不同的名称：

| 名称 | 类型 | 作用 |
|---|---|---|
| student | Java field name | Enrollment 中的对象属性 |
| student_id | Database column name | 数据库中的外键列 |

`mappedBy` 引用的是 Java Entity 中的字段名称，而不是数据库中的 column name。

因此：

```java
@OneToMany(mappedBy = "student")
```

是正确的。

而：

```java
@OneToMany(mappedBy = "student_id")
```

在 Enrollment 没有名为 `student_id` 的持久化属性时是错误的。

**总结：** `mappedBy = "student"` 表示 Student 是该双向关系的非 owning side，Enrollment 中的 `student` 字段负责维护关联关系。

## 9. LAZY 和 EAGER 有什么区别？

LAZY 和 EAGER 是 JPA 中的两种关联数据加载策略。

主要区别是关联数据的加载时机不同。

### LAZY（延迟加载）

LAZY 表示加载当前 Entity 时，不立即加载关联数据，而是在真正需要访问时才尝试加载。

例如：

```java
@OneToMany(
    mappedBy = "student",
    fetch = FetchType.LAZY
)
private List<Enrollment> enrollments;
```

查询：

```java
Student student =
    studentRepository.findById(1L).get();
```

此时通常只加载 Student。

当访问：

```java
student.getEnrollments().size();
```

Hibernate 才可能额外执行 SQL 查询 Enrollment 数据。

需要注意，延迟加载通常要求关联仍处于有效的持久化上下文中，否则可能出现 `LazyInitializationException`。

### EAGER（立即加载）

EAGER 表示加载当前 Entity 时，也需要加载其关联数据。

例如：

```java
@OneToMany(
    mappedBy = "student",
    fetch = FetchType.EAGER
)
private List<Enrollment> enrollments;
```

查询 Student 时，Hibernate 也会加载关联的 Enrollment。

但是 EAGER 不一定代表使用一条 JOIN SQL，也可能执行额外的查询。

### 对比

| 特性 | LAZY | EAGER |
|---|---|---|
| 加载时机 | 按需加载 | 立即加载 |
| 初始加载数据量 | 通常较少 | 可能较多 |
| 性能 | 避免不必要的加载 | 可能增加查询开销 |
| 潜在问题 | N+1、LazyInitializationException | 额外查询、数据量过大 |

### 为什么不应该全部设置为 EAGER？

因为并不是每次查询都需要所有关联数据。

例如，一个 Student 有很多 Enrollment，但是某个 API 只需要返回 Student 的姓名。

如果所有关系都设置成 EAGER，Hibernate 仍然可能加载大量不需要的数据。

这会增加：

1. 数据库查询次数。
2. 内存使用量。
3. 网络传输量。
4. API 响应时间。

此外，EAGER 也不能自动解决 N+1 查询问题。

通常建议根据业务需要选择加载方式，并使用 JOIN FETCH、EntityGraph 或 DTO 查询进行优化。

**总结：** LAZY 是按需加载，EAGER 是立即加载。关联关系通常不应该全部设置为 EAGER，以避免不必要的数据访问和性能开销。

## 10. 一次请求是如何到达 Database 的？

在 Spring Boot 应用中，一次数据库查询通常经过以下流程：

```text
HTTP Request
      |
      v
Controller
      |
      v
Service
      |
      v
Repository
      |
      v
Hibernate
      |
      v
JDBC
      |
      v
Database
```

以“根据 studentId 查询学生的 Enrollment”为例。

### 第一步：HTTP Request

客户端发送请求：

```http
GET /students/1/enrollments
```

表示查询 ID 为 1 的学生的所有选课记录。

### 第二步：Controller

Controller 负责接收 HTTP 请求、解析参数并调用 Service。

```java
@RestController
@RequestMapping("/students")
public class StudentController {

    private final EnrollmentService service;

    public StudentController(
            EnrollmentService service) {
        this.service = service;
    }

    @GetMapping("/{studentId}/enrollments")
    public List<EnrollmentDto> getEnrollments(
            @PathVariable Long studentId) {

        return service.getEnrollments(studentId);
    }
}
```

### 第三步：Service

Service 负责处理业务逻辑，并调用 Repository 查询数据。

```java
@Service
public class EnrollmentService {

    private final EnrollmentRepository repository;

    public EnrollmentService(
            EnrollmentRepository repository) {
        this.repository = repository;
    }

    @Transactional(readOnly = true)
    public List<EnrollmentDto> getEnrollments(
            Long studentId) {

        return repository.findByStudentId(studentId)
                .stream()
                .map(e -> new EnrollmentDto(
                        e.getId(),
                        e.getGrade()))
                .toList();
    }
}
```

DTO：

```java
public record EnrollmentDto(
    Long id,
    String grade
) {}
```

### 第四步：Repository

Repository 负责定义数据访问方法。

```java
public interface EnrollmentRepository
        extends JpaRepository<Enrollment, Long> {

    List<Enrollment> findByStudentId(Long studentId);
}
```

Spring Data JPA 可以根据方法名自动创建查询。

`findByStudentId` 表示根据 Enrollment 关联的 Student ID 查询选课记录。

### 第五步：Hibernate

Hibernate 负责将 JPA 查询转换成数据库可以执行的 SQL。

例如：

```sql
SELECT *
FROM enrollments
WHERE student_id = 1;
```

实际 SQL 可能包含参数占位符、别名和具体列名。

Hibernate 还负责把查询结果映射成 Enrollment Entity。

### 第六步：JDBC

JDBC（Java Database Connectivity）是 Java 访问关系型数据库的标准 API。

Hibernate 通过 JDBC 和数据库驱动执行 SQL，并读取查询结果。

底层操作可以类似于：

```java
PreparedStatement stmt =
    connection.prepareStatement(
        "SELECT * FROM enrollments WHERE student_id = ?"
    );

stmt.setLong(1, studentId);
```

这只是 JDBC 工作方式的示例。使用 Spring Data JPA 时，通常不需要手动编写这些代码。

### 第七步：Database

数据库接收 SQL，执行查询并返回结果。

例如：

| id | student_id | course_id | grade |
|---|---|---|---|
| 101 | 1 | 10 | A |
| 102 | 1 | 20 | B |
| 103 | 1 | 30 | A |

数据通过 JDBC 返回 Hibernate。

Hibernate 将结果映射成 Entity，Repository 返回给 Service，Service 将其转换成 DTO，最后 Controller 返回 HTTP 响应。

例如：

```json
[
  { "id": 101, "grade": "A" },
  { "id": 102, "grade": "B" },
  { "id": 103, "grade": "A" }
]
```

**总结：** HTTP Request 进入 Controller，Controller 调用 Service，Service 通过 Repository 查询数据，Hibernate 负责 ORM 和 SQL，JDBC 与数据库通信，最后查询结果返回客户端。
