## 1. Static Nested Class vs. Inner Class

A non-static inner class implicitly holds a reference to its enclosing `Outer` instance, allowing it to access the outer object's instance members. If a long-lived object retains the inner class instance, the `Outer` object may not be garbage-collected.

A static nested class does not hold this implicit reference, so it does not keep an `Outer` instance alive merely by existing. It is usually preferred when access to an outer instance is unnecessary because it avoids unintended object retention and potential memory leaks.


## 2. Type Erasure

Type erasure removes generic type parameters during compilation while preserving compile-time type checking. For example, `List<String>` and `List<Integer>` typically use the same runtime class for the same list implementation.

- `new T()` is illegal because the concrete type and constructor of `T` are not known.
- `new T[10]` is illegal because arrays require a runtime component type.
- `obj instanceof List<String>` is illegal because the runtime cannot check the erased generic type. `obj instanceof List<?>` is allowed.

A bridge method is a synthetic method generated by the compiler to preserve method overriding and polymorphism when type erasure changes method signatures.



## 3. PECS and Variance

**PECS means Producer Extends, Consumer Super.**

- `List<? extends Number>`: Elements can be read as `Number`, but non-null elements cannot safely be added because the actual element type is unknown.
- `List<? super Integer>`: `Integer` values can be added safely, but elements can only be read as `Object`. Other non-null types, such as `Double`, cannot safely be added.

Generics are invariant: `List<Integer>` is not a subtype of `List<Number>`, preventing unsafe writes. Arrays are covariant: `Integer[]` can be assigned to `Number[]`, but storing an incompatible value causes a runtime `ArrayStoreException`.


## 4. Annotation Retention Policies

- `SOURCE`: The annotation is discarded during compilation.
- `CLASS`: The annotation is stored in the `.class` file but is not required to be available at runtime. This is the default retention policy.
- `RUNTIME`: The annotation is stored in the `.class` file and available through runtime reflection.

Meta-annotations:
- `@Target` specifies where an annotation can be applied.
- `@Inherited` allows a class annotation to be inherited by subclasses.
- `@Repeatable` allows an annotation to be applied multiple times to the same declaration.

An annotation must use `RetentionPolicy.RUNTIME` to be read through runtime reflection.


## 5. Class Objects and Reflection

Common ways to obtain a `Class` object include:

- `MyClass.class`
- `object.getClass()`
- `Class.forName("fully.qualified.ClassName")`
- `classLoader.loadClass("fully.qualified.ClassName")`

`setAccessible(true)` requests suppression of Java language access checks, allowing reflection to access non-public members when permitted. The Java module system can restrict deep reflection. If the target package is not open to the calling module, an `InaccessibleObjectException` may be thrown.

`Method.invoke()` wraps exceptions thrown by the target method in `InvocationTargetException`, allowing callers to distinguish target-method failures from reflection invocation errors. The original exception can be retrieved using `getCause()`.
